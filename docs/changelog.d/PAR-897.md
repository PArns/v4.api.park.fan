### Fixed — an attraction's outage hours no longer count carried heartbeat rows

`attraction_hourly_history.downCount` counts the distinct hours a ride was
reported `DOWN`, and it counted the rows `writeHourlyHeartbeats` carries
forward as well: a frozen feed turned one reported outage into one outage hour
per hour it stayed frozen. Measured against production on 2026-10-21, per
attraction and park-local day: over 2026-09-01..10-07, before PAR-720 fixed the
writer, 4,163 of 253,752 rows (1.64 %) carried a `downCount` that is now
different, 77,450 outage hours against 67,594 (−12.7 %), with a median
overstatement of 2 h and 11 h at the worst row. Over 2026-10-08..10-20 it is
one row of 206,353. The daily rollup now reads observations only, like the slot
array beside it (PAR-729) and like the live path for today (PAR-898), which had
left the same day's figure dropping as it moved from the live query into the
rollup. Existing rows are not recomputed: none of them loses its outage, and a
backfill would rewrite the pre-PAR-729 slot coverage along with it.
