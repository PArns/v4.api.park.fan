### Fixed — ML history and system accuracy clamp `limit` and `days`

`GET /v1/ml/models/history` and `GET /v1/ml/models/metrics-history` passed
`limit` straight into TypeORM's `take`, and `GET /v1/ml/accuracy/system` passed
`days` into the aggregate query and its Redis key `accuracy:sys:${days}`, all
without an upper bound. Measured on 2026-10-02: `models/history?limit=100000`
returned all 30 `MLModel` rows in 64,811 B (about 2.2 KB per model), and the
response grows with every training run.

All three now go through `QueryIntPipe`: `limit` is clamped to 1–100 on both
history routes (the only frontend consumer, `getMLMetricsHistory`, asks for 50),
and `days` is clamped to 1–365, the same window as `days` on the attraction
detail. A non-integer value still answers 400.
`ml.controller.query-params.spec.ts` runs the three routes through the HTTP
pipeline.
