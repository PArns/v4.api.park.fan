### Added — the APNs key is uploaded in the admin, and both APNs environments work without a setting

The owner uploads Apple's `AuthKey_<KEYID>.p8` on the admin's page "Push (iOS)"
(`PUT /v1/admin/push/apns/key`) instead of setting `APNS_*` variables. The key
is stored sealed with AES-256-GCM under `ASSISTANT_SECRET_KEY` in the new table
`apns_settings`, wins over the variables, and is used from the next send on
without a restart; `GET /v1/push` then answers `apns: true`. Only a PKCS#8 EC
P-256 private key that signs a provider token is stored. No answer and no audit
row carries the key, both name it by a fingerprint. After an upload and on
demand the API asks Apple in production and sandbox whether it accepts the key,
with a background push to a token no device has, and the admin shows each answer
in German. The admin can also send a test notification to a registered device.

A device token only works in the environment that issued it. The app may now
send `environment: "sandbox" | "production"` with `POST /v1/push/devices`;
without it the server tries production, asks the sandbox on `BadDeviceToken` and
stores the one that accepted (`push_subscriptions.apnsEnvironment`). A token
both refuse is deleted as before. `APNS_PRODUCTION` only chooses which is tried
first. The provider token is no longer made new on every 403, which Apple
answers with `TooManyProviderTokenUpdates`. See
[push](frontend/push.md#the-apns-key-in-the-admin-v1adminpushapns).
