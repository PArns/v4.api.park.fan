### Added — `queues[].lastObserved`: when the ride's wait was last read, changed or not

`queues[].lastUpdated` is when the posted wait last changed, so a ride that has reported an
unchanged 5 minutes for five hours looked stale next to a fresh "Aktualisiert 13:10". Every queue
now also carries `lastObserved`, the last time a source delivered this ride. It comes from the
`attraction:last-seen:<id>` Redis key the wait-times sync already stamps on every poll, so there is
no new column and no new write; the read is one `MGET` per response build. A ride whose source
went quiet keeps its old value, and a heartbeat row is never taken for a reading. `lastUpdated` is
unchanged. Served by the park page, the attraction page, favorites and the park wait-times list.
