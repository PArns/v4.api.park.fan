### Fixed — `generate-hourly` can ask the model on every run instead of storing a cached answer again

The 15-minute job read CatBoost's hourly answer through `getRawParkPredictions`, whose Redis entry
lives 30 minutes and is evicted by nothing, so two of three runs stored the previous run's
inference again: the model was asked every 30–45 minutes, a served CatBoost slot could rest on
live inputs 45 minutes old, and `prediction_accuracy.prediction_time` recorded the replay rather
than the model run — the measured median lead of −0.6 minutes over 261,419 rows
([reader-facing accuracy](ml/reader-facing-accuracy.md)) cannot occur otherwise, because
ml-service rounds the base time up to the next slot. With `GENERATE_HOURLY_FRESH=true` the job
skips the cache read (the build still fills the cache for readers). Default off: it roughly
doubles the inference load on the shared host, so check a run's duration against the 15-minute
cadence before switching it on ([CatBoost](ml/catboost.md)).
