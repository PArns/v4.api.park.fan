### Fixed — an empty query integer takes the route's default, not 0

`?limit=` and `?radius=` reached `QueryIntPipe` as 0, so the route's default
never applied. The global `ValidationPipe` (`enableImplicitConversion`) turns a
`@Query()` parameter typed `number` into `+""` before any parameter pipe runs.
The seven integer parameters of `parks` (page, limit, days), `location/nearby`
(radius, limit) and `ml` (limit, days) now use the new `@QueryInt()` decorator,
which hands the raw string to the pipe; an empty or blank value counts as absent.
`?x=0` still parses as 0. `/location/nearby?radius=` now answers with the 1000 m
default instead of a 0 m radius. The `/parks/.../attractions` Swagger entries
for `page` and `limit` keep their `number` type through an explicit `type`.
