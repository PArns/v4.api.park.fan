### Security — creating a personal access token asks for the password, and the two-factor code

`POST /v1/admin/auth/tokens` takes `password` (required) and `totpCode` (required when the account has
two-factor on). A stolen session could until now mint a read-only token that outlived it for up to a
year. The password is checked with the login's scrypt verification, the code is single-use like at the
login (claimed with a conditional write, so two parallel requests cannot spend one step twice, and a
code already used to sign in is refused until the next step). Refusals are 401 `invalid-password`,
`totp-required` and `invalid-totp`, and 429 `rate-limited` with `retryAfterSeconds` from the action
limiter (`token-create`, 10 wrong attempts per account per 15 minutes; a missing code is not one).
Revoking a token needs neither. `GET /v1/admin/oauth/requests/:id` answers `createdAt`, so the consent
page can show the age of the request and warn on an old one. See
[authentication](admin/authentication.md#api-tokens-and-oauth-grants).
