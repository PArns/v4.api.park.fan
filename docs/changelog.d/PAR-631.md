### Fixed — `days` on four ML accuracy routes is clamped to 1–365

`accuracy/parks/:parkId/stats`, `accuracy/attractions/:attractionId/stats`,
`accuracy/trends/hourly` and `accuracy/features/analysis` read `days` with
`ParseIntPipe` and no bounds, so a negative value put the start date in the future.
They now use `QueryIntPipe` (default 30, 1–365), the same pipe PAR-609 put on
`accuracy/system`. A non-integer still answers 400.
