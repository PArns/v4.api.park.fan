### Changed — Chronos-2 serving is switched on in code, not by an env variable

`SERVE_CHRONOS_INTRADAY` was set in Coolify, but the API container still read `false`:
`docker-compose.production.yml` passed `${SERVE_CHRONOS_INTRADAY:-false}`, so Chronos-2 stayed a
shadow after the 2026-11-22 release. The switch is now the constant `SERVE_CHRONOS_INTRADAY` in
`src/ml/chronos-serving.ts` (`true`), and the compose file no longer passes the variable. Rollback
is `false` there and a deploy ([chronos-serving.md](ml/forward-archive/chronos-serving.md)).
