### Fixed — a TFT run that never finished no longer re-labels yesterday's forecast as today's

On 2026-10-09 all 231,480 `tft_forecasts` rows under `forecast_date = 2026-10-09` were byte-identical to 2026-10-08. The training had hung during a database outage (it was reset to idle only by the 07:31 container restart: "reset on startup"), the `train-nf` job's 90-minute poll loop ran out at 04:30 without throwing while the status still said `training`, and it then called nf-service `POST /forecast` — which re-persisted the cached `nf_forecast.parquet` from the previous night with `forecast_date = now()`. The calendar served a day-old TFT forecast as a fresh one, and the lead grid and the scoreboard counted it one day shorter than it was.

- `train-nf` now fails (it has `attempts: 1`, so no retry stacks a second training) on a poll timeout and on any end state other than `completed` for its own version, and it no longer calls `/forecast` at all: `train_runner` already persists the forecast it made.
- `persist_forecast` takes `forecast_date` from its caller instead of writing `now()`. The runner fixes it once and records it in the status file; `POST /forecast`, kept as a manual repair path, re-persists only the parquet of a `completed` run and only under that run's own `forecast_date`, and answers 409 otherwise.
- A hung runner no longer turns the following nights into silent skips. On 2026-10-09 the runner sat at `is_training` from 03:00 until the 07:31 container restart; the next night's pre-check would have read "already running" and returned success, until the reader's three-day window dropped TFT. `train-nf` now fails when the in-flight run started more than 90 minutes ago, nf-service kills a runner after `NF_TRAIN_DEADLINE_MINUTES` (120) and marks it `failed`, and `/train/status` reports `overdue` for a run past that deadline. `forecast_date` is fixed when the run starts, and `train-nf` warns when a completed run persisted 0 rows.
- A park chunk whose fit raised is still skipped without failing the run, but the counts (`info.chunks.total/ok/skipped`) are now in the status file and `train-nf` logs a warning when any were skipped.

A night without a forecast is safe: `getTftDailyPredictions` reads the freshest `forecast_date >= today - 3` per ride and day, so serving falls back to the previous night, then to CatBoost.
