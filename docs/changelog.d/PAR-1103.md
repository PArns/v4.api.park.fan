### Changed — an open park's frontend snapshot is revalidated about every 15 minutes

The frontend keeps a park's snapshot for a day and this API only pinged its
`park:` tag when the park opened or closed, so a crawler could read waits up to
a day old. The five-minute warmup now also sends the tag of every OPERATING park
whose last ping is 19 minutes or older, in the default stale-while-revalidate
profile; a park seen open for the first time after a restart is recorded, not
sent, and closed parks get no extra pings. See
[caching](architecture/caching-strategy.md).
