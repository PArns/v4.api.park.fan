### Added — `park.verify` records that a curated park value was checked against its source

`curatePark` skips a value equal to the stored one and then writes no audit row,
so a source check that confirmed a curated address had nowhere to go in the
database (PAR-601: `changed: []`, `auditId: null`, audit rows 624 before and 624
after).

`POST /v1/admin/content/parks/:id/verify` takes `fields`, `reason` and a
required `sourceUrl` and writes one `park.verify` row to `admin_audit_log`:
`before` holds the named curated fields as they stand, `after` is null, and the
park row and the caches are left alone. Unknown fields, an empty list and a
missing or non-http `sourceUrl` are rejected. A verify row cannot be undone.
History entries now carry `kind: "change" | "verification"`. No schema change.
