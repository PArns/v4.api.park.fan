### Added — Push for new guides, as its own device kind `guides`

A device that registers with `guides` in its `kinds` gets a notification when a
guide first appears in `media.park.fan/guides/<locale>.json`, opening
`/blog/<slug>`. It is the news trigger run over a second export
(`POST_FEEDS` in `NewsPushService`), not a copy: own seen-sets
`push:guides:seen:<locale>`, the same 6-hour limit on `publishedAt`, quiet
hours and kind gate. The first run fills the set with all 71 existing guides
and sends nothing; an edit or a guide that leaves the export and returns never
notifies again, because only the slug is compared and none is ever removed.
`newsParks` narrows news only. Nothing changes for an app that does not send
the kind. See [push](frontend/push.md).
