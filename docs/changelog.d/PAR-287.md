### Added — the curated works period reaches the API as `worksPeriod`

The two columns an editor fills under `/admin/attractions/<id>` —
`curated_out_of_service_from` / `_to` — have never left the backend. They gate
the trip planner and suppress the live outage estimate, and both of those are
silences: a ride under rebuild simply stops saying anything, and no payload
carries the reason. A visitor on the ride page reads a closed ride with no
explanation, which is the one case where we know the explanation.

Both endpoints that serve a ride now carry it: the attraction response and the
park payload's attraction list, as

```json
"worksPeriod": { "from": "2026-01-16", "to": "2026-03-03", "toUncertain": false }
```

Beside `outage` and deliberately not inside it. An outage is a fault the site
noticed; this is planned work somebody wrote down months ahead, and inside this
window no outage is reported at all. Absent means nobody has curated one — never
that the ride is running, since no feed announces a rebuild.

**`toUncertain` is the new curated column** (`curated_out_of_service_to_uncertain`,
nullable boolean, three states like every other curated boolean). A rebuild has a
season before it has a day: the park says "back in spring" for months, and an
editor who writes 2026-03-31 to get the window closed has written a date nobody
promised. The window still has to end somewhere — an open-ended one suppresses
this ride's outages for ever — so the flag keeps the date load-bearing and lets a
page write "probably until 31 March" instead of stating it. `null` is not
"certain": every window curated before this column existed carries it.

Two normalisations in `resolveWorksPeriod()`, so a client cannot render half a
statement. `toUncertain` is false whenever `to` is null, because an adverb needs
a date to qualify and the pair is what clearing the end date and not the checkbox
leaves behind. And the whole block is `null` rather than three nulls when nothing
is curated, which is the state of nearly every ride in the catalogue.

The dates are park-local and both bounds are inclusive, so whether the window
covers today is a question for the park's timezone — which the park payload
carries. Nothing here answers it: `isCuratedOutOfService()` still does, and the
live-poll projection is untouched, since a works period cannot change between two
five-minute polls.
