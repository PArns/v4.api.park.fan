### Added — a ride can hold several works periods

Rides had room for one curated works period, so a planned future window could
not be entered while the current one was still running. The new
`curated_out_of_service_periods` list holds up to 20 non-overlapping windows,
and every place that asks "is this ride in a works period" — the live outage
and "not yet today" lines, `/plan/day`, the nightly closure-gap and outage
reconstruction SQL, Parky's reopening answer — now asks whether any window
covers the day. The ride payloads gain `worksPeriods` (all windows, sorted);
`worksPeriod` stays and is the running window, else the next, else the most
recent ([works period](frontend/works-period.md)). The admin edits the list as
one field of the new type `periods`; the three single-window columns are still
read for this release and are cleared the first time a ride's list is saved
([curation](admin/curation.md)).
