### Changed — the H5 planner composer applies the TFT level only to d0–d2

`TFT_LEVEL_MAX_LEAD_DAYS` goes from 6 to 2. PAR-834 scaled a busy ride's H5
profile by the TFT day level up to six days ahead, because the benchmark's first
run — 37 autumn days — showed a win there. The full-period pass
(`ml-bench/results/20261009-baselines-v2/summary.md`, UC3 busy, `lvlh5_tft`
against the weekday median) keeps only d0–d2: d2 −0.415 [−0.699, −0.149], d3
−0.267 [−0.553, +0.002], d4–d6 straddling zero, and d30 +0.420
[+0.116, +0.708] significantly worse. Plain H5 beats the weekday median at every
lead in both passes, so from d3 on it is what the flag serves. The composer is
still behind `PLAN_DAY_H5_COMPOSER` (off in production), so nothing a user sees
changes. The forward archive's `plan_day_shadow_routed` surface comes from the
same `h5LevelFor` call, so the live A/B now measures the d2 rule; routed rows
for busy rides at d3–d6 stop being written and the scorer reads plain H5 under
that name there, as it already does for quiet rides.
