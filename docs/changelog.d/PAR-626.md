### Fixed — a repeatable job whose next run lost its hash is re-registered instead of failing as `__default__`

Redis runs `allkeys-lru`, and the delayed job hash of a daily cron sits untouched
for up to 24 h, so eviction takes it while its id stays in `delayed`. Bull then
runs an empty hash as `__default__` ("Missing process handler"), and because the
job's `opts` went with the hash it never schedules the run after it. On
2026-10-02 this had stopped 17 daily crons, `calculate-percentiles` among them,
until the next restart.

`QueueSchedulerService.hasRepeatableJob` now also checks the job materialised for
the entry's `next` run (`materialisedRepeatJobId`, the id Bull derives in
`lib/repeatable.js`). A missing or nameless hash removes the entry so it is
registered again. `registerScheduledJobs` re-runs every hour as a repair pass
instead of only at startup. The eviction policy itself is not changed here.
