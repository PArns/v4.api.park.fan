### Added — Calendar-grid TFT as a nightly shadow, compared live in the forward archive

nf-service now trains the calendar-grid TFT (PAR-1033) every night after the
served TFT, in the same run and under the same lock, and writes it to its own
table `tft_forecasts_shadow` (`LIKE tft_forecasts`; the served table's key has
no model version, so two variants cannot share it). `NF_GRID_SHADOW`, default
on, switches it off; it never runs concurrently with the served run, keeps
`windows_batch_size`, roughly doubles the night's GPU time and never fails the
night. The forward-archive scoring reads the shadow level each archived
TFT-levelled ride-day would have had at its origin and pairs it against the
served TFT on the calendar questions as `tft_grid` ("TFT mit Lücken-Raster":
`cal_rank`, `cal_busier`, `cal_far`), with no offline verdict yet and a new
decision "Kalender: TFT mit Lücken-Raster" judged on 08.01.2027. No paired
definition bump: no existing row changes. The new table is registered in the
duplicate merge and the E2E schema. Because the table only exists after nf-service's first
shadow write, the merge skips it (and the other raw-SQL sub-service tables,
`pcn_forecasts` and `tft_forecasts`) while `to_regclass` is null; before that
fix every attraction merge, including the one inside `syncParks`, would have
failed with 42P01 until the first shadow night.
