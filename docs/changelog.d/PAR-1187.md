### Added — Parky, the chat assistant, and site feedback

New module `src/assistant/` ([assistant](frontend/assistant.md)). `POST /v1/assistant/chat` answers questions about parks, rides, wait times, forecasts, weather and park.fan's posts with Claude Haiku 5.5, streamed as server-sent events, in the page's language and with the informal address. Parky reads through a fixed list of tools: most reuse the admin MCP server's handlers, plus a per-hour ride forecast, park weather, parks near the visitor and directions. On request it also acts on the page, and the widget carries that out: show a park or ride card, open a park.fan page, ask for the position, or plan a day (open it, add rides or a block, sort it). There is no web search and no admin data.

`POST /v1/assistant/session` trades a solved Turnstile challenge for a session token. The token is signed and valid for two hours, and chat, rating and feedback refuse a request without one. It is not bound to an address, so a phone changing networks keeps its chat. Limits apply per session: questions per ten minutes and per day, and 150,000 tokens a day. Per address (an IPv6 /64 counts as one) only issuing sessions is limited. A daily token budget covers all chats together. The Claude key is entered in the admin, stored sealed with AES-256-GCM under `ASSISTANT_SECRET_KEY` and never shown again. Chats are stored without an address and pruned after 90 days by the nightly `assistant` job. Feedback goes to `site_feedback`. The admin reads all of it under `/v1/admin/assistant/*`. `AdminTurnstileService.verify` can now also check a token's action.
