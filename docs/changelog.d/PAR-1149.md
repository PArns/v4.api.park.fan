### Fixed — ml-service's holiday, schedule and weather-climatology caches evict expired entries

The three caches checked their TTL on read but never removed an entry, and
their keys carry date ranges and park sets, so they grew every day; only
gunicorn's worker recycling (`ML_MAX_REQUESTS`) bounded the memory. They now
drop expired entries on every write with the helper the recent-wait-times cache
already used (moved to `db.py` and shared). pcn-service's `fetch_actuals_local`
reads `PCN_MIN_WAIT` instead of a literal 5. Worker recycling stays as the
safety net until a worker's RSS is measured over a day without it. See
[performance](ml/performance-optimizations.md).
