### Fixed — prediction rows now carry the schedule status they were computed with

`predict.py` set `status` on every prediction row, but `PredictionResponse` did not
declare it, and pydantic v2 drops undeclared keys without a word. The field never
reached the API, so `MLService.storePredictions` wrote NULL into
`wait_time_predictions.status` on all 3157154 hourly and 35983223 daily rows that
existed before this change.

The accuracy feedback filter one screen below it reads that column — `status ===
"OPERATING" || status === null`, commented "excluding scheduled closures". With NULL
on the left it excluded nothing, so declaring the field would have activated it for
the first time. Measured over 7 days of stored hourly rows before the change, that
would have removed 1375 of 2336057 rows (0.059 %) from accuracy scoring, all of it
three parks with a patchy schedule source. None of them is a scheduled closure:
`predict.py` drops CLOSED rows before inference and `schedule_filter` drops anything
outside an OPERATING window, so the only rows left to lose were hours on days nobody
published a schedule for, in parks a ride wait proved were running. The filter now
keeps `UNKNOWN` explicitly and recorded coverage is unchanged.

Rows written before this change keep NULL, which the filter still accepts.
