### Changed — ML ops cleanup: REINDEX of pcn_forecasts_pkey, TFT forecast retention, atomic PCN checkpoints, stable TFT chunks, heartbeat-free bench truth

- **Weekly `REINDEX INDEX CONCURRENTLY pcn_forecasts_pkey`** (`db-maintenance/reindex-pcn-forecasts-pkey`,
  Sunday 19:10 UTC): the rolling prune left the PK at 10.1 GB against a 5.2 GB heap.
  Starts only Sunday 19:10–19:30, `statement_timeout` capped to end by 20:03,
  `lock_timeout` 60 s, skipped while another index build, a vacuum of the table or
  another maintenance session runs; an interrupted run's invalid `_ccnew`/`_ccold`
  copy is dropped. `pcn_forecasts` is a plain table, so CONCURRENTLY works
  (db-health-runbook §5b).
- **Retention for `tft_forecasts`, `tft_forecasts_shadow` and
  `tft_forecasts_shadow_drivers`**: 120 days by `forecast_date`
  (`db-maintenance/prune-tft-forecasts`, 04:35 UTC, 200 k-row ctid batches, at most
  40 a night shared by the three tables, served table first). A shadow nf-service
  has not created yet is skipped. The oldest origin any reader needs is 107 days (forward-archive shadow
  scoring); ml-bench exports now carry at most 120 days of TFT origins. No batch
  starts after 04:48 UTC (each capped to end by 04:50, the VACUUM); a stopped run
  logs the rows left and continues the next night. The ~5–6 M rows the first run
  deletes are exported to the NAS by hand before the deploy (db-health-runbook §5b).
- **Served TFT changes tonight**: the new park chunking (below) changes which parks
  share a model, so every park's served daily TFT forecast changes with no shadow
  run before it (owner decision). Watch the TFT accuracy for a week.
- **pcn-service checkpoints are written atomically**: temp file in the same
  directory, fsync, `os.replace`; a crash mid-write no longer leaves a truncated
  model.
- **nf-service park chunks**: only parks with at least one usable wait row, ordered by
  (country, park id) — a new park no longer shifts every later park into another
  chunk (and another model).
- **ml-bench `build` drops heartbeat rows by default** (`--no-drop-heartbeats` for the
  old target). Builds made before this kept them and are not comparable.
- **Container memory limits**: analysis and recommended limits in
  docs/deployment/coolify.md as an owner decision; compose unchanged.
