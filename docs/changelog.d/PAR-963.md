### Fixed — `/v1/discovery/nearby` rejects malformed coordinates instead of locating by IP

`parseFloat` and `parseInt` cut trailing garbage, so `radius=5km` became 5 and
`lat=48.1abc` became 48.1, and a sent but invalid pair (`lat=91`, `lat=abc`, or
only one of the two) silently fell back to the IP lookup — an answer for a
different place that looked like a hit. Coordinates are now read with
`Number()` and range-checked, and any sent-but-unusable pair answers 400; the IP
lookup still runs when neither is sent. `radius` and `limit` go through
`QueryIntPipe`: a non-integer answers 400, an out-of-range integer is clamped
(0–10000 m, 1–50) where it used to answer 400.
An empty `lat=`/`lng=` counts as sent and answers 400. An empty `radius=` or
`limit=` now reads as 0 (as everywhere `QueryIntPipe` is used), so radius 0 and
limit 1, where it used to fall back to the defaults; no caller sends one.
