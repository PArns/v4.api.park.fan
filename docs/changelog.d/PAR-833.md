### Fixed — a degraded plan/day answer is no longer cached for 15 minutes, and the hourly profile builds once

`GET .../plan/day` answered a day whose hourly profile had failed
(`ridesUnavailable.reason = data_unavailable`) with the same
`Cache-Control: public, max-age=900, s-maxage=900, stale-while-revalidate=1800`
as a complete day, so Cloudflare kept the "try again shortly" answer for up to
45 minutes after the fault ended. `HttpCacheInterceptor` takes an optional
predicate for such bodies and sends them `no-store`; complete days keep the 15
minutes.

`ParkHistoricalStatsService.getParkHourlyProfile` was a Redis get followed by the
4-6 s query with nothing in between, so every parallel request on a cold key ran
its own copy. Concurrent callers now share one build through `SingleFlight`, and
a failed build sets `<key>:failed` for 90 s so the callers after it fail without
another query.
