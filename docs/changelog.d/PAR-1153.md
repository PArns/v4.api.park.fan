### Security — no full address in any log line, a network in the audit log

`LoggingInterceptor` wrote `request.ip` into the line of every error, slow request and admin request, and the admin login wrote the caller's
address when Turnstile refused it. Now an admin request line carries at most a /24 (IPv4) or /48
(IPv6) from `truncateIp`, which moved from the auth service to `src/common/utils/request.util.ts`;
every other route's line, and the Turnstile refusal, name no address. `redactUrl` also hides the `ip`
query parameter of the location and favourites routes, and the slow-query file and the error line of a
failed statement cut any address among the bound parameters to its network. A spec reads every file in
`src/` and fails on a logger call that names an address. See [the rule](rules/no-address-in-logs.md).

`admin_audit_log.actor_ip` held the whole address of the admin account behind every row, with no end. The
network answers what the column is for (did a session come from somewhere else), so the audit service now
stores `truncateIp` of the
caller's address, and a nightly job (`admin-audit` / `sweep-addresses`, 01:15 UTC) clears it on rows past
90 days (the row stays) and cuts every full address already stored to its /24 or /48, in batches, in
TypeScript with the same helper. A second run changes nothing, and the job logs counts, never an address.
The column was nullable `text` already and stays so, which keeps the change out of `synchronize`. The first
run clears or cuts every stored address and cannot be undone; the read-only count to take before the
deploy is in [the audit log](admin/authentication.md#address-retention), next to what the log keeps about an
account.
