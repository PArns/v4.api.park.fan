### Added — ml-bench: Granite PatchTST-FM-r2, Granite TTM-r2 and TabPFN-TS plug-ins, and a licence guard

Four new benchmark arms: `patchtst_fm` (zero-shot, no covariate input, a real q95 from its
99-quantile head), `ttm_r2` (zero-shot, no covariates), `ttm_r2_ft` (the covariates as
exogenous channels, fine-tuned every 28 days on truth before the origin) and `tabpfn_ts`
(the daily level only, with known-future covariates, against `driver_level` and `wt_med`).
PatchTST-FM-r2 (Apache-2.0 or OpenMDW-1.0) and TTM-r2 (Apache-2.0) may be served; TabPFN-TS
runs on the TabPFN-3.5 weights, whose licence rules out production use, so it is
benchmark-only. Every foundation plug-in now declares its licence verdict. A
benchmark-only model marked as a serving candidate fails as soon as the class is defined,
and `run-*.json` records both fields. The optional `requirements-par1066.txt` also fixes
`requirements-par1063.txt`, which silently upgraded numpy to 2.x through jax's
`ml_dtypes`. `run.sh` passes `HF_TOKEN` / `TABPFN_TOKEN` through from the caller's
environment. Nothing has been run on the GPU yet; the combined run command is in
`docs/ml/ml-bench.md`.

### Changed — Python dependencies of every ML service on current releases

`ml-service`, `nf-service`, `pcn-service` and `ml-bench` move to the newest release of each
dependency that is at least two weeks old: numpy 1.26.4 → 2.4.6 and pandas 2.2.3 → 2.3.3 in
every image, scikit-learn 1.6.1 → 1.9.1, neuralforecast 3.1.8 → 3.3.0, pyarrow 23 → 26,
fastapi/starlette/uvicorn/gunicorn/pydantic to their newest, and torch pinned at 2.11.0, the
newest cu128 build (it was an open `>=2.7.0` floor). gunicorn now loads `UvicornWorker`
from the `uvicorn-worker` package, since `uvicorn.workers` is deprecated. numpy 2 lifts the
ml-bench holds on jax (0.6.2 → 0.10.2) and on the PAR-853 numpy override. Held on purpose,
each with a comment: pandas 3, numpy 2.5 (Python ≥ 3.12), SQLAlchemy 2.1 and cu130 torch.
A CatBoost model + metadata pickle and a PCN checkpoint written with the old pins load and
predict bit-identically with the new ones, and the reverse, so a rollback is safe. How
versions are chosen and how to re-run the check: `docs/development/python-dependencies.md`.
