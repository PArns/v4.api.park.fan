### Security — a search's `%` and `_` match only themselves

An injection audit of the API, the admin and the Python services found no SQL, command, code, path
or header injection that input can reach: every interpolated SQL value is a constant, a fragment
the code builds, an allow-listed identifier or a number forced through `Math.trunc`, `int()` or
`float()`. It found one small gap. The public search (`GET /v1/search?q=`) and the admin's content
and audit-log searches bound the visitor's text as a parameter, but `%` and `_` kept their
wildcard meaning, so `q=__` matched every row on the database paths. `likeContains` and
`likeStartsWith` (`src/common/utils/like-pattern.util.ts`) escape them, as the assistant's chat
search already did, and the search reads at most 100 characters of `q` (`SEARCH_QUERY_MAX`), cut
rather than refused.

Outside the code and left for a decision: Bull Board publishes port 3001 without a login
(`docker-compose.production.yml`), and TypeORM drops `undefined` from `find` conditions
(`invalidWhereValuesBehavior: ignore`).
