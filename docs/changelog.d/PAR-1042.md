### Added — CatBoost's day level is archived beside TFT's, so the two can be compared live

TFT and CatBoost never levelled the same ride-day, so "switch the CatBoost
daily level off" could only be judged at 90 days, against the weekday
average. The forward archive now keeps, on every planner row whose level is
TFT's, the CatBoost level for the same ride-day
(`forecast_archive_curves.catboost_day_peak`, nullable, never served), read from the cached CatBoost
daily answer the served daily read already starts from — one extra cache read
per 06:00 / 07:00 park capture, no ml-service call. The scorer pairs it with
the served TFT day peak as `catboost_shadow` (PEAK and the day ranking D7),
the CatBoost columns of `cal_rank`, `cal_busier` and `cal_far` show it live,
and the decision `catboost_daily_off` now rests on those cells plus
`cal_far_90`. Those three CatBoost cells carry `expect: "not_better"`
(honoured by `deriveDecisionState`): switching CatBoost off needs the live
gate met WITHOUT CatBoost beating TFT, never a CatBoost win. The shadow is
scored only where the weekday average exists, so a park's first two weeks add
nothing to it. The D7 read path ranks each model's days separately. The paired
definition stays 3 (no existing row changes meaning). See
[forward archive §9.1](../ml/forward-archive/model-comparison.md#paired-scoring).
