### Performance — the wait-times sync no longer waits for the cache warmup

The `wait-times` job (every 5 min, one at a time) spent ~210 s of a ~263 s run
on the cache warmup that followed the fetch, not on the fetch. Measured on
production on 2026-10-09: fetch and writes for all 211 parks 51 s, park caches
~68 s, top-1000 attractions ~92 s, park occupancy + heartbeats ~43 s — and about
125 s of the warmup is the deliberate 1 s pause between batches. Bull 4.16.5
schedules only the next cron slot from `max(prevMillis, now)`, so missed slots
are skipped rather than caught up; a long run only made the next one start late
(the 15:55 run started 106 s late), by less than one run's duration.

The warmup now runs on its own queue (`live-cache-warmup`,
`LiveCacheWarmupProcessor`), enqueued at the end of every sync. Its three steps,
their order and their pacing are unchanged; a request with a newer one already
waiting returns at once, and one failed step no longer skips the other two.
Heartbeats stay in the sync job. Expected `wait-times` run: ~55 s instead of
~263 s.

Upstream access stays one request stream per source. The park warmup is not
DB-only: for a park whose schedule reads CLOSED, `buildIntegratedResponse`
re-checks queue-times, Wartezeiten or ThemeParks.wiki. Before every park batch
the warmup therefore waits until no `wait-times` job is active (polling every
2 s, giving up on the round after 5 min), so warmup and sync never fetch at the
same time — as when both ran in one job. The sync's own fetching is unchanged:
sequential per park, Wartezeiten still rotated 10 parks per cycle.

This does not explain the up-to-23-minute staleness seen between 08:00 and
10:00 UTC on 2026-10-09 — that start lag cannot exceed one run's duration, so
its cause is still open. Both jobs now log a `⏱️ … phases {json}` line with
per-phase wall-clock, including per-source fetch time (`fetch.<source>.SumMs`),
to find it the next time it happens.

Also: `weather-current-cron` moves from `0 */6 * * *` to `0 7,19 * * *`. At
00:00 and 12:00 it fired beside the full run, which already saves the current
day, and 06:00 is the CatBoost retrain.
