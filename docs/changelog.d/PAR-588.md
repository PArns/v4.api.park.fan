### Tested — `GET /v1/parks/popular` keeps its limit between 1 and 100

PAR-588 reported that the `limit` parameter of `ParksController.getPopularParks`
(`DefaultValuePipe(20), ParseIntPipe`) had no upper bound. The handler already
clamps it with `Math.min(Math.max(limit, 1), 100)`, so a request with
`limit=100000` reads 100 ranked parks, and the only frontend consumer
(`getPopularParks(100)` in `lib/content-urls.ts`) asks for exactly that. Nothing
asserted it, though: `parks.controller.query-params.spec.ts` covered the
attractions list, the attraction detail and the calendar, but not this route.

The spec now runs the route through the real HTTP pipeline for seven values:
absent and `abc` both read 20, `5` reads 5, `0` and `-3` read 1, `100` reads
100, and `100000` reads 100. No production code changed.
