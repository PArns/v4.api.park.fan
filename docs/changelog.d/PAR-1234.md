### Added — the site statistic counts the bot hits it drops, and the overview returns them as `bots.hits`

The collector dropped a bot's hits (`isBotUserAgent`, an empty User-Agent
included) twice over, in `collect()` and again in `record()`, and counted
none of them, so the admin could not show what share of the traffic is bots.
`record()` now adds them to the day's drop counts under the new reason
`dropped:bot`, once (the check in `collect()` is gone). The nightly
`snapshot-visitors` run keeps a finished day's count in the new table
`site_bot_days` (`day`, `hits`; additive, created by `DB_SYNCHRONIZE` on
deploy), and `GET /v1/admin/analytics/overview` returns the window's sum as
`bots: { hits }` (today and yesterday read live; `null` under a language or a
filter). Counting starts with the deploy: a window reaching a day that was not counted
returns `null`, never a made-up zero. See [site analytics](frontend/site-analytics.md).
