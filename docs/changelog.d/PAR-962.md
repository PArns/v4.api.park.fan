### Fixed — GET /parks/:continent/:country/:city/:park/seasons answered 500 on an impossible date and started the list on the UTC day

`from=2026-02-31` passed the shape check and reached Postgres, which refused it; the endpoint now answers 400, and so does any non-empty `from` or `to` that is not a real `YYYY-MM-DD` day. The check is `isRealIsoDate` in `date.util.ts`, shared with the admin path. Without `from` the list now starts on the park's own day and ends 365 days later, where it used to start on the UTC day (a day early in Tokyo in the morning, a day late in California in the evening). `current=true` in the admin season list uses the park's day when the list is scoped to one park (`parkId`); the cross-park list has no single zone and keeps the UTC day.
