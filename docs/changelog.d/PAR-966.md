### Fixed — the hourly rollup no longer reads heartbeat and reconciliation rows

`HOURLY_AGGREGATE_SELECT`, behind every `queue_data_aggregates` row, was the
last reader of `queue_data` that counted our own bookkeeping as an observation.
Both reads now apply `observedReadingsSql`: in `observed` a carried heartbeat no
longer becomes a sample, and in the anchor LATERAL a `system-reconciliation`
CLOSED row no longer hides the real OPERATING reading before it — so that
placement can add a bucket as well as drop one. Measured in PAR-755 over
13.–20.10. it changes nothing today (241,263 buckets either way, 0 p50 changes,
363 → 323 ms per day window); it is a guard for when the heartbeat writer slips
again, as in PAR-720 (35.4 % of buckets). No backfill of older buckets.
