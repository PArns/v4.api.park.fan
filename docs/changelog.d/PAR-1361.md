### Added — Parky's knowledge base, read only when a question needs it

Background Parky needs for a few questions now lives outside the prompt, in
`src/assistant/knowledge/`, one file per topic. The prompt's `# Knowledge` lists each topic with
one line on when to read it, and the new tool `read_knowledge` returns its text, so a chat that
needs none pays only for the list. Topics are files, not an admin table, because they change
answers like the prompt does and go through review, the eval and `SYSTEM_PROMPT_VERSION`.
`knowledge.spec.ts` checks names, length (at most 4,000 characters) and the prompt's list.
Background: [Parky's knowledge base](frontend/assistant.md#parkys-knowledge-base).

The first topic, `forecasts`, holds the three crowd readings (now, the day's forecast, the day so
far) and why they differ, how Fancast forecasts, and what to do when a visitor calls a forecast
wrong. It comes from the feedback of 15 November 2026, where „Andrang jetzt: hoch" on Europa-Park's
today panel and „Normal" for the day so far read as a wrong forecast. Parky now explains first and
passes it on with `submit_feedback` only when the same reading still shows two ways or the visitor
asks. Three eval cases (`forecast-two-readings-de`, `forecast-how-made-en`, and
`crowd-today-no-knowledge-de`, which must not read it); the eval has 99.
