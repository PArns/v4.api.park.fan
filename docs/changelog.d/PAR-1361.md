### Added — Parky's knowledge base, a wiki edited in the admin and the MCP, read only when a question needs it

Background Parky needs for a few questions now lives in the table `assistant_knowledge`, one row
per topic (`topic`, `readWhen`, `text`, `enabled`), outside the prompt. The prompt's `# Knowledge`
lists every enabled topic with one line on when to read it (the slot `{{knowledge topics}}`,
filled per chat by `systemPromptWith`), and the new tool `read_knowledge` returns the topic's text,
so a chat that needs none pays only for the list. `AssistantKnowledgeService` serves the enabled
topics from a per-process copy for a minute, so an edit reaches the next chat without a deploy.

Editors write it in the admin (`GET/PUT/DELETE /v1/admin/assistant/knowledge[/:topic]`) or the
admin MCP (`assistant_knowledge`, `write_assistant_knowledge` with a dry run,
`delete_assistant_knowledge` with confirm). Every write is audited with the whole topic before and
after (`entityType` `assistant_knowledge`), which is the topic's history. An empty table is seeded
once at boot from `src/assistant/knowledge/`. Background:
[Parky's knowledge base](frontend/assistant.md#parkys-knowledge-base).

The first topic, `forecasts`, holds the three crowd readings (now, the day's forecast, the day so
far) and why they differ, how Fancast forecasts, and what to do when a visitor calls a forecast
wrong. It comes from the feedback of 15 November 2026, where „Andrang jetzt: hoch" on Europa-Park's
today panel and „Normal" for the day so far read as a wrong forecast. Parky now explains first and
passes it on with `submit_feedback` only when the same reading still shows two ways or the visitor
asks. Three eval cases (`forecast-two-readings-de`, `forecast-how-made-en`, and
`crowd-today-no-knowledge-de`, which must not read it); the eval has 99 and fills the slot from the
seed.
