### Added — Parky's chats say whether they came from the website or the app, with a token statistic and a switch for the app alone

A session opened with a data key now carries the key's id in its signed token, and a new chat
stores it as `source` (`web` or `app`) and `apiKeyId`; tokens issued before the deploy keep
working and count as `web`. `GET /v1/admin/assistant/conversations` filters by `source`, and
`GET /v1/admin/assistant/stats/tokens` sums chats, messages, tokens by kind and cost per UTC day
and source, per data key, and names the visitors and chats that spent most. The nightly prune
keeps those sums per day, source and key in the new `assistant_usage_day_stats`, so they outlive
the 7 days the chats are kept. The setting `appEnabled` switches Parky off in the app alone:
`POST session` with a data key and `POST chat` on an app session answer 503 `off`, and
`GET /v1/assistant/config` gains `appEnabled`. The MCP has the source on `assistant_conversations`
and the new `assistant_tokens_report`. See [assistant](frontend/assistant.md).
