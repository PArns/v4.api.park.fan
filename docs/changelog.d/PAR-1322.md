### Changed — after 2.21.0: deleting revoked keys, ticket names without `.h`

- **A revoked data API key can be deleted for good.**
  `POST /v1/admin/api-keys/:id/delete` answers 204, 409 for a key that is not
  revoked yet, 404 for none. It deletes the row, then the key's Redis
  counters and caches its two secrets as refused, and writes `api-key.delete`
  to the audit log, where the key stays visible
  ([API keys](frontend/api-keys.md)).
- **Ticket names no longer carry the planner's `.h` token.** Five seed
  products named their hopper option "(… with .h)": Disneyland Paris' 1-day
  ticket, Disneyland Resort's 1-day and 2- to 5-day tickets, Walt Disney
  World's ticket with Water Park and Sports, and Universal Orlando's
  date-based ticket. They now read "(1 Park, or 2 Parks)", "(1 Park Per Day
  or Park Hopper)", "(Park Hopper Plus)" and "(1 park per day or
  park-to-park)". A catalog already saved in the database keeps its names
  until it is edited in the admin.
- **The admin MCP server writes park seasons and ticket products.** A token
  with the new `admin:write` scope, chosen by an editor or owner when a
  connection is approved or a personal access token is made, also writes as
  an editor: `create_trip_season`, `update_trip_season`, `delete_trip_season`
  and `import_trip_seasons` (the researched season files, a dry run unless
  told otherwise) beside `list_trip_seasons`, and `upsert_ticket_product` and
  `archive_ticket_product` beside `list_ticket_products`. Each calls the admin
  route's service, so a write is checked, audited under the account and
  published as in the admin; a delete needs `confirm`. Reading stays the
  default and an existing grant stays read-only. `import-seasons.mjs` sends
  its file through the tool with such a token instead of an admin session.
  The admin's season list also filters by `parkId` and `region`, and
  `GET /v1/admin/content/seasons/:id` reads one season
  ([writing](admin/mcp.md#writing), [seasons](admin/curation.md#seasons)).
