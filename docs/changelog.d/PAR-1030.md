### Fixed — CatBoost features mean the same thing at training and serving time

Training (`features.py`) and serving (`predict.py`) computed several features
differently. Serving now follows training's definition for all of them:

- `avg_wait_last_1h` got the live wait on every forecast row, up to 48 hours
  ahead. That overwrote the same-hour profile that rows more than 24 hours
  ahead had just been given. The live wait now reaches only rows up to 3 hours
  ahead (`LIVE_LAG_MAX_LEAD`); later rows get the profile.
- `wait_time_velocity` was the change over the last 30 minutes divided by 6,
  which is a twelfth of the per-hour scale training uses. It is now the mean of
  the last six hourly changes, the same as training, on rows up to 3 hours
  ahead, and 0 beyond.
- `time_since_park_open_mins` was measured from today's opening on every row.
  It is now measured per row, from the opening of that row's own day.
- `is_bridge_day` was one flag for today, sent by the API and applied to every
  row up to a year ahead. It is now worked out per date in the ML service, and
  the API no longer sends it.
- The weekday/weekend rolling features are split on the park-local weekday,
  not the UTC one. This changes both paths.
- In training, `park_occupancy_pct` no longer counts the row's own wait, which
  is the value being predicted.
- The interaction features are recomputed after training dropout.
- `queue_data` heartbeat rows are dropped from the training data and from the
  rolling context (PAR-1039).

- Training dropout of `avg_wait_last_1h` also sets `wait_time_velocity` to
  0, the pairing serving uses beyond 3 hours.

Retrain: the occupancy, interactions, dropout and heartbeat changes take effect
with the next nightly training. The serving fixes apply from deploy. The
serving side of the weekday split (`fetch_recent_rolling_stats`) also applies
from deploy, while the current model was trained on the UTC split; until the
next training the two disagree near local midnight on weekend boundaries.
Trigger a training run right after deploy to close that window.
