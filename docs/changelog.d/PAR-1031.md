### Fixed — Forecast weather per row, in training's units

The CatBoost service gave every row of a request the climatology of the FIRST
row's month, and rows past the end of the hourly forecast read 20 °C, 0 mm and
weather code 0 — a 60-day calendar in late October was predicted with October
weather in December, and as a dry, mild day wherever the forecast had run out.
Each row now reads its own park-local month's climatology, and rows past the
forecast are filled from it.

The units now match training too (PAR-1032): training reads one `weather_data`
row per park-local day, while serving fed the hourly forecast in as it came, so a
2 mm hour was read as a nearly dry day. The forecast is now reduced to that day's
precipitation and snowfall totals, wind maximum and weather code.
`precipitation_last_3h` is the day's total / 8 on both sides; in training it was
a 3-hour rolling sum over every ride's row of the park, so it grew with the
number of rides. The temperature sinusoid put its minimum at 14:00 instead of its
maximum (training, serving fallback and the API's synthesised hourly forecast);
it now peaks at 14:00, and a 0 °C daily minimum is no longer read as 15 °C.

Training-side changes (`precipitation_last_3h`, the sinusoid) take effect with
the next 06:00 UTC retrain.
