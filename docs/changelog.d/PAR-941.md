### Security — public write limiters key on an address the caller cannot rotate, and a push send no longer resurrects a deleted subscription

The trip, ride-alert and show-follow write limiters keyed on the first
`X-Forwarded-For` hop, which the caller writes — Cloudflare appends the real
address after it — so a random value per request bought a fresh bucket every
time. They now use `getRateLimitIp`: `X-Forwarded-For` only from our own
frontend proxy (valid throttle bypass key), otherwise `CF-Connecting-IP`
(validated as an IP), otherwise the socket address. `CfThrottlerGuard`'s
unverified fallback keys on the socket address too, because with
`trust proxy` on, `req.ip` is that same caller-written hop. `getClientIp`
(GeoIP) is unchanged.

`POST /v1/push/subscriptions` had no write limiter at all; it now has its own
60-an-hour bucket beside the ride-alert and show-follow ones.

`PushService.send` wrote its outcome back with `save()` on the row loaded at the
start of the cycle, which re-inserted a subscription deleted mid-cycle and wrote
back stale keys, trip and topics. Success is now an `update` by id, a failure an
atomic `increment` followed by a conditional delete at the failure limit.

Also: `parkIdsBySubscription` binds its id list as one array parameter
(`= ANY(...)`) instead of one parameter per id, and `PushService.findByIds`
dedupes its ids.
