### Changed — the batch dry run of attraction merges names the curated rows it would delete

`POST /v1/admin/merge-duplicate-attractions` with `dryRun: true` (the default without `winnerId`/`loserId`) now adds `droppedCurations` to every planned pair. The list comes from `previewMerge`, the same function behind the single-pair rehearsal, so the two cannot disagree. Before, the batch report named slug, winner and reason only, and a following `dryRun: false` run deleted whatever curated ride profile the losing side held without the rehearsal having said so. The cost is 3 statements per planned pair (two attraction reads, one `attraction_ride_profiles` SELECT, plus one more where the loser holds a profile), on a dry run only. A pair whose preview throws is listed under `failed`.
