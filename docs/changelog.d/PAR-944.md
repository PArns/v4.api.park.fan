### Removed — dead DTOs, helpers, unused admin ML endpoints and four dependencies

Code nothing reached, confirmed by a word-boundary search over `src`, `test`,
`scripts` and the frontend repository before each deletion.

- **DTO files**: `attraction-query`, `destination-query`, `destination-response`,
  `destination-with-parks`, `holiday-response`, `status-response`,
  `wait-times-response`, `availability-response`, `restaurant-query`,
  `restaurant-response`, `show-query`, `show-response`, `showtimes-response`.
- **Classes and types in files that stay**: `ParkOccupancyResponseDto`,
  `StatisticsResponseDto`, `SystemAccuracyDto`, `TrendsDto`, `SystemHealthDto`,
  `ParkPredictionRequestDto`, `PredictionItemDto`, `PredictionResponseDto`,
  `ForecastResponseDto`, `ShowTime`, `CalendarMonthResponse`,
  `ParkDowntimeCoverageDto`, `EntityScheduleResponse`, `OpenHolidaysResponse`,
  `WartezeitenErrorResponse`.
- **Helpers**: `parseDateInTimezone`, `getCountryNameFromISO`,
  `getWeatherCategory`, `getInfluencingCountries`, `prioritizeNeighbors`,
  `filterByRadius`, `isThemeParksWikiId`, `parseSortParameter`.
- **Bull handler** `backfill-park-baseline` on the `p50-baseline` queue — never
  enqueued. `backfill-attraction-hourly-history` stays.
- **Admin ML endpoints with no caller** (the admin dashboard reads only
  `ml/dashboard`, `ml/models/metrics-history`, `ml/monitoring/alerts`,
  `ml/monitoring/anomalies/stats` and `ml/monitoring/tft/performers`):
  `GET ml/models/history`, `GET ml/accuracy/parks/:parkId/stats`,
  `GET ml/accuracy/attractions/:attractionId/stats`,
  `GET ml/accuracy/trends/hourly`, `GET ml/accuracy/features/analysis`,
  `GET ml/monitoring/drift/model`, `GET ml/monitoring/drift/features`,
  `GET ml/monitoring/drift/features/:featureName`,
  `POST ml/monitoring/alerts/:id/acknowledge`,
  `POST ml/monitoring/alerts/:id/resolve`, `POST ml/monitoring/alerts/check`,
  `GET ml/monitoring/anomalies`, `POST ml/monitoring/anomalies/detect`. With the
  four writes gone the monitoring controller has no guarded route left, so
  `MLModule` no longer imports `AdminAuthModule`. The service methods only these
  routes reached went with them: `analyzeFeatureErrors`, `getParkAccuracyStats`,
  `getModelHistory`, `acknowledgeAlert`, `resolveAlert`, `getAnomalies`,
  `getFeatureDriftHistory`. `getAttractionAccuracyStats` stays — the accuracy
  badge falls back to it. The crons keep drift, alert and anomaly detection.
- **Entity** `MLAccuracyComparison` (`ml_accuracy_comparisons`) and its two
  merge-strategy entries. Nothing wrote the table. `synchronize` does not drop
  tables, so it stays in production until it is dropped by hand
  (`DROP TABLE ml_accuracy_comparisons;`); it has no foreign key, so a merge
  that no longer moves its rows is not blocked by them.
- **Dependencies**: `@nestjs/axios` (`OpenHolidaysModule` imported `HttpModule`
  but nothing injected `HttpService`), `uuid` (the two entity id generators use
  `randomUUID()` from `node:crypto`; the `uuid` override in
  `pnpm-workspace.yaml` stays for transitive users), and the dev dependencies
  `ts-loader` and `source-map-support`.
