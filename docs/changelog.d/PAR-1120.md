### Added — the admin overview names the parks PCN should forecast and does not

`pcn-service/forecast.py` skipped a park for one of several reasons and said
so only in its log. Every skip now carries a reason, and the forecast job's
result in the status file (`GET /status`) splits them into `idle` (closed park,
stale feed, unchanged origin) and `blocked` (no model, empty panel, too few
slots, no trained ride in the window, an error). `/v1/admin/ml-overview` reads
it: the `pcn` row lists the blocked parks as `blockedParks` and counts them in
the note, because those parks are served CatBoost without anyone seeing it.
The last result stays in the file while the next tick runs.
[PCN: the forecast tick](ml/pcn.md#the-forecast-tick).
