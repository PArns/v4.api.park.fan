### Fixed — /schedule and /weather reject windows over 90 days

Both endpoints parsed `from` and `to` without a limit, so `from=2000-01-01` returned
166 KB in 1.38 s and every new `from`/`to` pair created its own
`park:derivedHours:{park}:{from}:{to}` Redis key and its own query on
`attraction_hourly_history`. They now call `validateDateRange(from, to, 90)` like
`/calendar` and `/best-days`; a longer window is a 400 with no cache header. The
defaults (30 days ahead for `/schedule`, 30 days back for `/weather`) are unchanged.
