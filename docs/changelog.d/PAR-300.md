### Fixed — the free-flow flag survives an attraction merge

`open_with_park` marks a ride you can walk onto whenever the park is open — a
playground, a water playground, a walkthrough with no queue. Somebody types it;
no feed states it. It was the one hand-editable column on neither of
`AttractionMergeService`'s inheritance lists, so a merge whose losing row carried
it and whose surviving row did not threw the statement away, leaving nothing to
notice it by.

It could not join `INHERITABLE_COLUMNS`, which fills a column only where the
winner's value is absent. The column is `boolean NOT NULL DEFAULT false`, so the
winner always holds a value and the test never fires. PAR-297 left it tracked
rather than fixed, on the reading that carrying it would mean treating a stored
`false` as "nobody said" against what the descriptor declares.

**That reading was backwards, and the descriptor is the evidence.**
`ATTRACTION_CURATED_FIELDS` gives `openWithPark` a `defaultValue` of `false`,
documented as what the column holds when nobody has decided anything, and
`attractionFieldViews` scores `overridden` against that value rather than
against null — which is the only reason the catalogue does not wear a "curated"
badge on all 7 355 rows. So the merge now reads the stored `false` exactly as
the editor already does, on a third list, `INHERITABLE_DEFAULTED_COLUMNS`: the
survivor takes the loser's value where the survivor is sitting on the declared
unset value and the loser is not. The rule is one-directional — a loser's
`false` never clears a survivor's `true`, because an absence of a statement may
not unset one.

The alternative was making the column nullable so that "nothing said" and "no"
become distinguishable. That is the tidier data model and the more expensive
change, and it fails in the direction this entry is about: `open_with_park` is
read as a bare boolean in seven raw statements — six in
`queue-percentile.processor.ts` (lines 188, 213, 299, 356, 446, 819) and one in
`data-quality-monitor.service.ts` (line 182). Six of the seven are negated, and
under three-valued logic `NOT open_with_park` is `NULL` for every null row, so
those rows leave their `WHERE` clause silently, with no exception and no red
test. The seventh is positive (`WHERE open_with_park AND is_seasonal = true`)
and drops the same rows the same way. That comes on top of a migration over a
full table and the reversal of `AdminCurationService`, which writes `false`
rather than null for this column on purpose.

Measured against production on 2026-09-18, before the change: 34 of 7 355
non-retired attractions are marked free-flow, and **none** of the 47 pairs
`findDuplicatePairs` offers carries the flag on either side. The automatic path
was losing nothing that day, and the guard is not a repair — the merge endpoint
also takes a `winnerId`/`loserId` of its caller's choosing and never consults
that list. Nor is the loss tilted toward the losing side as expected: 30 of the
34 are fed by a live source, so a free-flow row does not systematically lose
`chooseDuplicateWinner`'s first criterion.

`previewMerge` names the column in `inheritedColumns` for free, because it
derives them from the same function the write path uses. The descriptor spec
drops its last inheritance exception, holds the declared unset value against the
descriptor's `defaultValue`, and refuses a column on the new list that has no
`defaultValue` at all — the drift that let the works period sit off every list
for eleven days is the one being closed here too.
