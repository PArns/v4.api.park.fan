### Added — re-issue candidates: a retired ride beside a younger live ride, for a human to merge or dismiss

ThemeParks.wiki re-issues seasonal attractions under a new id and often a new
name (`HAUNTED HOUSE: SAW: Legacy of Terror` → `SAW Legacy of Terror`), which
the sync's exact-name claim from PAR-682 cannot see. `findReissueCandidates`
lists every absence-retired row with a younger live row within 30 m, both
upstream ids, last readings and a name hint (`reissueNamesMatch`), minus pairs
marked `not_a_duplicate`. Served on `GET /v1/admin/reissue-candidates` and in
`data-quality`; the nightly job warns with the count of likely pairs.

Nothing merges by itself. A merge from the admin passes the new
`adoptLoserExternalId`, so the survivor takes the id the feed lists — without
it the sync grows the removed row back when the names differ.
