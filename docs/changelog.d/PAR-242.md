### Fixed — a browser client calling the API cross-origin can read `Retry-After` on a 429

`Retry-After` is not a CORS-safelisted response header, and `enableCors` in `src/main.ts` exposed no headers, so `response.headers.get("Retry-After")` returned `null` in a browser even though the header was sent. Both CORS branches that allow origins (production whitelist and development) now set `exposedHeaders: ["Retry-After"]`. The `retryAfterSeconds` body field is unchanged. park.fan itself is not affected: its push and trip calls go through a server-side relay.
