### Performance — Parky spends fewer tokens per answer

One answer to "Magic kingdom" with two tool calls cost 8,606 uncached input
and 15,228 cache-read tokens. Only the system prompt and the tool list carried
a cache breakpoint, so every round after the first sent the question, the
history and the earlier tool results again at full price. A second breakpoint
now moves with the conversation (`moveCacheBreakpoint`), so each round reads
what came before from the cache at a tenth of the price. The tool schemas lose
zod's `$schema` and the uuid pattern (15,220 to 12,949 characters per round),
`get_park`'s `scheduleToday` holds today only instead of every coming day (36
entries for Magic Kingdom, about 3,500 characters), `get_ride` drops the day's
single readings and unknown facts, `get_park_live` the park's clock and zone,
and `show_card` returns what the card shows, so the sentence after it needs no
second lookup. A park closed all day no longer gets tomorrow's hours on its
card as today's. Details in
[the assistant page](frontend/assistant.md#the-answer-loop).
