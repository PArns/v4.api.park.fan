### Added — The admin MCP server edits key permissions and decides key requests

The API keys page could do more than the MCP tools: a key's permissions and the developers' key
requests were only reachable in the admin. `update_api_key` and `create_api_key` now take
`permissions`, the whole list the key carries afterwards. `api_keys` shows each key's permissions
(null for a key from before them, which reads everything), the developer account and request it
came from, and `awaitsPickup`. Only a key held by a developer account can wait for pickup; a key
issued by hand was shown in clear when it was made. Five new owner tools run the request routes:
`api_key_requests`, `approve_api_key_request` (with a dry run, and no secret in the answer, since
the developer picks the key up), `reject_api_key_request`, `reopen_api_key_request` and
`delete_api_key_request` (with a dry run). Anyone can register and fill in the form, so what the
applicant typed comes back under `visitorData` with its own notice
([admin MCP server](admin/mcp.md)).
