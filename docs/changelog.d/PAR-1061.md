### Documented — one covariate source, read as of an origin (design)

`docs/architecture/covariate-source.md` lists what each model service computes today for schedules, holidays, weather and events, and whether it can ask what was known at an origin. None can, because `schedule_entries` and `weather_data` overwrite in place. It also proposes the fix: append-only fact logs written by NestJS (schedule day versions, weather forecast issues, holiday coverage versions), one shared `covariates/` derivation that every service reads with an explicit `origin`, size estimates, an 11-step migration with a parity test per step, and six owner decisions. No code changes.
