### Removed — the unreachable priority merge in `syncParks`

`syncParks` had a third branch that moved shows, restaurants and rides from a
"losing park" into a name duplicate and then deleted the loser. The loser was
looked up by the incoming `externalId` in the same map whose hit skips the
branch, so `losingPark` was `null` on every run and the branch never executed.

The block is removed with `mergePriorityDuplicateLoser` and its rollback error,
about 290 lines in `parks.service.ts` and the specs that drove the helper
directly. A name duplicate under a different `externalId` is still updated in
place. Parks that exist twice are merged by the ghost path in `syncParks` and by
`repairDuplicates`, which are unchanged. No schema change.
