### Added — a planner report: funnel, ways in, steps, blocks, tools, sharing and the parks planned most

The trip planner sends a funnel of its own events now (the frontend's `lib/analytics/planner-funnel.ts`).
`GET /v1/admin/analytics/planner` and the MCP tool `planner_report` read them like the search report
reads `search_*`:

- the funnel from an opening to a started, optimised and shared day: `startRate` counts only the
  days started in an opening (`plan_day_started`'s `source` is a way in, `none` with the panel
  shut), and optimisations and shares are counts per started day, since a day is re-planned and
  shared as often as anyone likes;
- each way in (`planner_opened`'s `source`) with the days started in such an opening;
- the wizard's steps, blocks added and removed by kind and source, the optimiser's modes, the fit
  assistant and its levers, undo, cleared days, shared plans opened and adopted, and push;
- openings by page type and device, and per period;
- the parks with the most days started and the rides added most, named through `SiteEntityNames`,
  a merged park or ride counted for its winner as on the event page.

The report takes the same window, filters and `datacenter` as the others and reads the daily
rows where they exist. `/plan/day` now sends `parkId`, each ride's `attractionId` and each show's
`showId`, which the planner's events name them by; the slugs stay the plan's keys. See
[site statistic](frontend/site-analytics.md) and [`/plan/day` rides](frontend/plan-day/rides.md).
