### Fixed — the orchestrator parallelism spec no longer reads the wall clock

`multi-source-orchestrator.service.spec.ts` asserted that two 50 ms fetches finish in under 90 ms. At load average 26 the run took 759 ms and `pnpm test` went red with no code change. The spec now holds both fetches open on one promise and asserts that the second one has started before the first resolves. A serial implementation never starts the second fetch, so the assertion fails there (checked by serialising `fetchParkLiveData` locally). 3 of 3 runs passed with 12 busy loops on 4 cores.
