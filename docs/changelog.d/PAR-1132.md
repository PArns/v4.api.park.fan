### Fixed — search returns a ride's slug as stored, and its cache key carries `limit`

`/v1/search` ran attraction `slug` and `url` through `cleanSlugSuffix`, so `apollo-13` came back as
`apollo` and a `-2` twin's hit pointed at the other ride; both are now the stored slug. The Redis
key `search:fuzzy:v1:{type}:{q}` left `limit` out, so a `limit=5` request could get a `limit=20`
list and the reverse; it is now `search:fuzzy:v2:{type}:{limit}:{q}`, and the warmup fills the
default limit park.fan asks for. The controller comment no longer claims the 60 s edge cache
matches Redis, which keeps 5 minutes ([search contract](frontend/search.md)).
