### Changed — an attraction merge names the single curated values it deletes

A merge keeps the survivor's own value of a curated column (`curatedName`, `curatedMinimumHeight`, `curatedSeasonMonths`, `hasSingleRider`, `rcdbId` and the rest of `ATTRACTION_CURATED_FIELDS` that is on `INHERITABLE_COLUMNS`) and then deletes the losing row. Where the loser held a different value of such a column, that value used to disappear without a trace. `previewMerge` now lists those values in `droppedCurations` as one `attractions` entry per pair, so the batch dry run from PAR-209 shows them as well, and `mergeAttractions` logs them before the DELETE. Equal values and sync-owned columns such as `landName` are not reported. The inheritance rule itself is unchanged.
