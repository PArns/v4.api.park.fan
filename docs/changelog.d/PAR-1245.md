### Added — Efteling's maintenance calendar keeps its rides' works periods

A weekly job (`manual-metadata` / `sync-efteling-maintenance`, Monday 10:20 UTC,
also `POST /v1/admin/sync-efteling-maintenance` with `{ dryRun? }`) reads
efteling.com's in-maintenance page and writes its windows into the rides'
[works periods](frontend/works-period.md) through the admin's curation path:
an audit row per ride, one cache eviction, the frontend revalidated twice.
Windows it writes carry `source: "efteling-maintenance-calendar"`; it moves and
removes only those (removals only before they start), never touches a
hand-written window, and an admin save keeps the marker on a window whose dates
it left alone. A page without its "Closed" list fails the job and writes
nothing. Against the 2026-11-06 page the first run adds 12 windows to 9 rides
([Efteling sync](admin/efteling-maintenance-sync.md)).
