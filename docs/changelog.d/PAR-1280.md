### Fixed — Parky knows the page in every language

The widget sends the path the browser shows, and the site writes some segments in the reader's
language: `/de/glossar/airtime`, `/fr/meilleure-periode-pour-visiter`, a park's
`/durchschnittliche-wartezeiten` or `/met-kinderen`. The page service knew only the English ones,
so in five of six languages a glossary page named no term, the best-time, planner and how-it-works
pages named nothing, and a park's calendar, average-wait and with-kids pages were looked up as a
ride with that slug. `parsePage` now reads all six spellings of each segment
([assistant](frontend/assistant.md#the-page-the-visitor-is-on)), and a segment named like an
inherited object key ("constructor") matches no page.
