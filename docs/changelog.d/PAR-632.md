### Fixed — `models/metrics-history` returns the newest models, not the oldest

`MLModelService.getMetricsHistory(limit)` sorted by `trainedAt` ascending before
`take`, so with `limit` below the row count it returned the oldest models.
`ml_models` is pruned to the newest 30 plus the active model
(`MLTrainingProcessor.cleanupOldModels`), so the frontend's `limit=50` never hit
this, but any smaller `limit` did. The query now sorts descending and the result is
reversed, so the response stays oldest first.
