### Removed — the shape-service and the TFT-vs-CatBoost scoreboard

Two shadow pipelines that nothing read any more are switched off (owner
decision, 2026-10-12).

- **Shape service**: the `shape-service/` container (both compose files,
  `SHAPE_SERVICE_URL`), the `shape-shadow` queue with its build / forecast /
  score crons (09:00 / 09:30 / 10:00 UTC), `POST /v1/admin/shape/:action`, the
  `shapeComparison` block of `/v1/admin/system-health`, the `shape` section of
  `/v1/admin/ml-comparison`, the `shape` row of the ML overview and the decision
  `shape_service_off` (it is taken). It delivered nothing to the app and showed
  no measured advantage: its board compared a 14-day forecast against
  CatBoost's ≤24-hour one.
- **TFT-vs-CatBoost scoreboard**: the `score-comparison` job (nf-training, 07:00
  UTC), the `catboost_daily_forecasts` snapshot it wrote, the `model_comparisons`
  entity, the `comparison` block of `/v1/admin/system-health` and the `daily`
  section of `/v1/admin/ml-comparison`. Nobody read it after the admin page moved
  to the model comparison (PAR-862). The scheduler now removes the leftover
  `nf-score-comparison-cron` from Redis at boot, so no run fails as "Missing
  process handler".
- **`MLHealthCheckProcessor`**: dead code, never registered.

The four tables `shape_forecasts`, `shape_comparisons`,
`catboost_daily_forecasts` and `model_comparisons` leave the merge dependency
list and the E2E schema (two entity-less merge tables remain: `pcn_forecasts`,
`tft_forecasts`). They are not dropped by code; production dumps and drops them
after the deploy. `ml-bench export` no longer reads `catboost_daily_forecasts`,
so `lvlh5_cbd` stays empty on new exports.
