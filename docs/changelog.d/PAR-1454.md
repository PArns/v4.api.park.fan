### Added — derived kinds in the admin's ride list, a `no_kind_fits` review mark, and MCP tools for paid queue products and the app's news export

The admin's ride list (`GET /v1/admin/content/parks/:id/attractions`) sent only `attraction_kind`,
the kind an editor chose, so park.fan's admin had to fetch the public park payload to show the kind
the nightly derivation (PAR-1453) had set. Each ride now carries `derivedAttractionKind` and
`attractionKindSource` (`curated`, `derived` or null) beside the raw column. In the curated-field
view, the `attractionKind` field serves the derived kind as its `resolvedValue` where no editor
chose one, and its hint no longer says a kind cannot be derived. The data-quality report's
`attractionsWithoutKind` adds `withoutKindRefs` (`{ id, name, slug }` per ride) beside the names,
so a client stops matching rows by name; the names stay. A ride that none of the kinds fits, such
as a pool or a Christmas market, can now take a `no_kind_fits` review mark, and the report leaves
it out of both lists. `POST /v1/admin/review-marks` checks every mark before it writes any and
answers 400 for the first that fails, such as an unknown kind, an id that is not a uuid or a
second ride on a single-ride mark; it used to store any kind and answer 500 for a bad id. See
[attraction kind](frontend/attraction-kind.md#in-the-admin) and
[review marks](architecture/attraction-status/review-marks.md).

`park_purchases`, new in the admin MCP server, lists a park's paid queue products per park-local
day (Lightning Lane Multi Pass, Premier Pass, one ride's Lightning Lane) from the schedule rows
`/schedule` serves, with price, sold-out state and the ride a per-ride product is for.
`news_export_status` reads park.fan's new `/api/news-export/status` and reports how far the app's
export on media.park.fan lags the site. `run_news_export` starts a new run of `publish-media.yml`
through `/api/news-export/run`; it needs the editor role, is a dry run unless told otherwise, and
writes `news-export.run` to the audit log, also when park.fan does not confirm the start within
25 s. Both send the revalidation secret. A 504 from park.fan, which the site sends when GitHub's
dispatch call timed out or failed after the request went out, counts as such an unconfirmed start:
the audit row says `outcome: "unknown"`, and the tool tells the model to look at the workflow's
runs on GitHub before it starts another. `curate_park_attractions` takes `adoptDerivedKind` to
write a ride's derived kind into `attraction_kind`, and the curation tools say that
`attractionKind` takes `GAME` and that null hands a ride back to the rule. `data_quality` passes
the refs, cut to `limit` per park, and drops the bare names; `review_mark` takes `no_kind_fits`.
See [admin MCP](admin/mcp.md#paid-queue-products).
