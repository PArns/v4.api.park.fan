### Added — an attraction slug that stops answering redirects with a 301 instead of a 404

Parks have had `park_slug_aliases` for a while; attractions had nothing, so
every merge that removed a loser's `-2` slug and every slug corrected by hand
turned an indexed, linked URL into a permanent 404.

`attraction_slug_aliases` (new table, created by `synchronize`) maps an old
slug to the attraction. The attraction route answers such a slug with a 301 to
the current path, keeping `?days=`. `AttractionMergeService` records the slug
it removes inside the merge transaction, and the loser's older aliases move to
the winner through `ATTRACTION_DEPENDENCIES`. A slug changed by hand needs its
alias row in the same step — see `docs/admin/curation.md`.
