### Fixed — A Search Console import a deploy interrupts no longer blocks the next one for hours

The import's Redis lock lasted three hours and was released only when the run
ended. A run lost with its process, a deploy that could not wait for it, kept
the lock for the rest of those hours: the restarted job, the nightly cron and
every "import now" found it taken and returned without doing anything, and the
status's `runningSince` reported the dead run as running. The lock now lasts
five minutes and the run renews it every minute, stamping its row's new
`heartbeat_at` column with the same beat, and `runningSince` follows that
stamp. On a shutdown the run stops before its next unit, within the 20 s a
deploy grants, records "Stopped by a shutdown" as its error and releases the
lock, without failing the job. See
[Search Console](frontend/search-console.md#the-import).
