### Added — `hasVirtualLine`, and the `VIRTUAL_QUEUE` branch that never existed

A ride with a virtual line had no way of saying so. Efteling's Danse Macabre
runs one and its page showed CLOSED and a single-rider badge, because a virtual
queue that is handing out nothing at this moment publishes no queue at all —
there is nothing in `queues` to read it off, and reading it off `queues` is the
mistake `has_single_rider` was written to avoid in the first place.

So `has_virtual_line` is the same kind of column and for the same reason: a
static fact about the ride, nullable, written by hand and by no sync. Null stays
"nobody looked" rather than "no", which is what keeps the ride page from
publishing our own bookkeeping as the park's statement. It is seeded from the
rides that have ever reported a `RETURN_TIME`, `PAID_RETURN_TIME`,
`BOARDING_GROUP` or `VIRTUAL_QUEUE` row; the statement and the three things in
it that are load-bearing are in `docs/admin/curation.md`. The live badge built
from the queue types is untouched — one is the ride's layout, the other is
today's reading of it.

The descriptor in `curated-field.spec-list.ts` is the whole of the admin change.
The editor generates itself from what the API describes, so the column appears
there with no frontend commit.

`VIRTUAL_QUEUE` was the other half. It has been a member of `QueueType` while
being a value no code path could act on: the `QueueData` payload type had no key
for it, so the ingestion switch had no branch to map, and a park publishing one
stored a row carrying a status and nothing else — no state, no return window.
The delta strategy had the same gap one function down, so even a row that
somehow held a window would not have been saved again when the window moved.
Both are fixed against `RETURN_TIME`'s branch, which is the same three fields,
and both now have a spec that goes red without them.

The three hand-written lists of queue types now read the enum instead of
repeating it. The one in `parks.controller.ts` had drifted furthest: it offered
`PAID_FASTPASS`, which has never been a member of `QueueType`, and omitted three
that are.
