### Added — search finds a park by its abbreviation, and the search report ranks what was opened

`/v1/search` knew the curated abbreviations only as page copy: „EP" listed Thorpe Park first,
„SFGA" Snorri's Saga, „USS" a carousel. The park index now carries them, and a query that is one
of them ranks its park above every other match and counts as verbatim, so it stays first on a day
the park is closed. See [search](architecture/search.md#a-parks-abbreviation-is-its-name).

The frontend now sends the opened park's, ride's, show's or restaurant's UUID with
`search_result_clicked` and `search_browse_clicked`. `GET /v1/admin/analytics/search` and
`search_report` rank the parks and rides opened from a search (`topParks`, `topRides`), a merged
one counted for its winner. The ranking is one helper, `rankedEntities`, which the planner report
now uses too. See [site statistic](frontend/site-analytics.md).
