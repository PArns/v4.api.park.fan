### Changed — background and admin reads over the heavy tables run under a statement_timeout

Until now only the downtime reconstruction, the forecast archive and the H5 profile bounded their reads; the rest ran with the server default of 0, so a plan that flipped could hold a snapshot for hours (PAR-820, the compression-policy outage of 2026-09-28). Six more callers now go through `queryWithLimits`, with deadlines taken from the production slow-query log of 2026-10-10: the downtime profile rebuild (12.3 s measured, 120 s limit), the show schedule pattern read (24.5 s, 180 s), the ML training read in `ml-service/db.py` (42.6 s, 300 s, set there with `SET LOCAL` because the Node helper does not reach that process), the outage service's four per-park reads (under 10 s, 30 s limit) and the admin downtime measurement (the reconstruction's per-scan-day ceiling). The retired forecast scoreboard tables from the same listing no longer exist (PAR-870).
