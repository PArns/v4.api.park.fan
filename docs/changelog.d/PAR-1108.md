### Documented — `CLAUDE.md` routes, `docs/README.md` maps every page, and the docs match the code

`claude.md` was 36 KB of paragraph-long index entries that every session read in full, and its
lower-case name kept Claude Code from loading it automatically. It is now `CLAUDE.md`, about 4 KB:
what the repo is, where each kind of task starts, the rules that apply to every change, and how the
docs are kept. `docs/README.md` lists every page once, and `docs/rules/README.md` every standing
rule, with three new ones: `park-timezone`, `the-entities-are-the-schema` (there are no migrations
and `DB_SYNCHRONIZE=true` runs in production, which the old §2 got wrong) and `publish-outside-in`.

Every doc was checked against the code and condensed; restatements became links. Mixed documents
became folders: `attraction-status/`, `ride-downtime/`, `frontend/plan-day/`, `ml/forward-archive/`,
`ml/ml-bench/`, `ml/foundation-models/`. `docs/ml/model-overview.md` is the entry page for which
model serves what. Implemented plans, one-off reviews and the German PCN review were folded into the
reference docs and deleted, `DEPLOYMENT.md` into `docs/deployment/coolify.md`. New contract page:
`docs/frontend/effective-status.md`. `todo.md` is gone: open items are Linear issues
(PAR-1092 to PAR-1100 and others). The root `README.md`, also the page at api.park.fan/, lists
the current routes and every data source.
