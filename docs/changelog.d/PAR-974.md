### Fixed — a search that names something stops listing its near-misses

`/v1/search` matched a ride's land by trigram similarity, and "phantasialand"
against "Fantasyland" scores exactly the 0.30 threshold, so the park came back
with ten Disney Fantasyland rides under it. "taron" listed 24 results (Red Baron,
Taco Loco), "dollywood" 26 (every "Hollywood …"). Once one match carries the
query as typed (the name, the name without punctuation, a ride's land, a park's
city, country or continent), `search()` now drops the matches only the typo
tiers found (`isLiteralHit`, step 1b). A query with no literal match keeps all
of them: "fantasialand" still finds Phantasialand, "taaron" still finds Taron.
Against an index built from the production API (211 parks, 7,447 rides),
65 of 104 test queries changed and every typo query stayed the same.
