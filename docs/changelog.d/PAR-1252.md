### Fixed — The queue screen and the MCP count every queue; `system_health` fits the answer limit

`queue-status` (and the MCP `queue_status`) counted fifteen hand-picked queues out of more than
forty. When celestrial rebooted on 2026-11-07, `live-cache-warmup` failed and the data-quality card
showed it, but the queue screen and the MCP did not. The counts now cover every queue in
`BULL_QUEUE_REGISTRATIONS`, the list the data-quality monitor already reads, and `queue-failures`
can read the failures of any of them.

The MCP `system_health` answered `section: ml` with about 131k characters. The MCP cuts every answer
at 100k, so the end of the ML half never arrived. The two PCN boards now return their verdict and
count; their per-day rows come back only when you ask with `boardRows`
([MCP](admin/mcp.md)).

New MCP tools `model_comparison` and `model_comparison_day` serve the admin's model comparison: the
question × model matrix with state, switch checks and the live paired difference, and one ride-day's
archived curves against the actual waits. Until now `ml_overview` carried only the matrix's counts.

`GET /v1/admin/model-comparison` gives each model a `family` (in the app, baseline, profile, new
daily model, foundation model) and lists the `families` in column order with German headers. The
admin page can then group its columns
([model comparison](ml/forward-archive/model-comparison.md#endpoints)).

Two of the matrix's texts misled. A cell whose longest lead had no data yet read "0 von 14 Tagen",
even when the shorter leads had three weeks of data. Its note and expected date now name the
longest lead instead. An offline run whose expected date has passed now reads "überfällig seit …"
and carries `overdue: true`, where it used to look like an upcoming date.
