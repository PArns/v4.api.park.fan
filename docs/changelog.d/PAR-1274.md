### Changed — Parky reaches a park by its name and gets the live summary with the park card

Parky has at most four rounds of tools per answer. In the chats of 3 to 9 November, 3 of 5
`search_parks` calls only found the id for the next tool, and `get_park_live` came beside
`show_card` for the same park in 5 of 7 answers.

- Every `park` parameter takes a name too (`resolvePark`, shared with the admin MCP): a slug no
  park has goes to the site's search, which gives the park when it finds only one, or exactly one
  whose name is the reference ("europa park" meets "Europa-Park"), and the candidates otherwise.
- `show_card` kind `park` returns `get_park_live`'s whole summary as `live` beside what the card
  shows; both read one helper, `parkLiveSummary`.
- The system prompt (version 37) sends a park name straight to the tool it needs and never calls
  the card and `get_park_live` for one park.
