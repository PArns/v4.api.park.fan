### Fixed — the first hour of the served wait forecast is the wait now

The persistence blend served the current wait in the first hour only for rides
with at least 40 minutes, and 94 % of rides sit below that, so almost every ride
got the raw PCN forecast 15 minutes ahead — where the current wait beat it by
1.7 minutes on the live archive. The first hour now serves the current wait for
every ride whose wait is at least 5 minutes; the 40-minute gate stays for the
1–3 hour ramp, and the lead is measured from now rather than from the start of
the current 15-minute slot. The current wait counts only while the ride is
OPERATING, so a ride that just went down is no longer forecast at its last
queue (PAR-1029). The crowd level of a PCN slot is blended the same way, so it
agrees with the wait shown beside it, and a PCN slot no longer carries
CatBoost's uncertainty band (`uncertaintyMinutes` is null there: PCN publishes
no upper quantile).
