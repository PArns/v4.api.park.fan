### Added — PAR-830 level drivers and a time-weighted target in the TFT grid shadow

A second calendar-grid TFT shadow beside PAR-1041's grid-only one
(`tft_forecasts_shadow`) reads the
level drivers PAR-830 ranked highest, as NaN-free futr_exog with neutral values and
flags where unknown: opening hours relative to the last four same weekdays
(`hours_ratio`), the late close (`close_vs_ref`), the first operating day after a
closure (`closed_days_before`), whether the window was published as of the origin
(`sched_known`, from `schedule_entries.updatedAt`), and the change of the own
region's school-break state (`school_break_first_day` / `_last_day` / `_day_after`,
0 past the PAR-1049 coverage). Its target is the time-weighted daily P90 over the
15-min grid of the published operating window (readings carried ≤ 3 h, as
`rideQ90`), instead of the P90 over change-log rows. The served TFT is unchanged.
It is its own model: a third nightly run into its own table
`tft_forecasts_shadow_drivers` (model version `<v>-grid-drivers`), paired in the
forward archive and the admin model comparison as `tft_grid_drivers` with its own
decision, so the grid-only `tft_grid` keeps running and the two are compared
separately. `NF_SHADOW_DRIVERS` (default on) switches only this run; the night's
`train-nf` job takes ~40–50 min instead of ~25. A futr_exog has one value per day, so the schedule is as-of
"published before the day" in the history and exactly as published in the future
frame — see `docs/ml/neuralforecast-tft-evaluation.md`.
