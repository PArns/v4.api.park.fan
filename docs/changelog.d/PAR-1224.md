### Documented — the beacon reads an AI assistant's `utm_source` and counts a page only on screen

The frontend beacon (park.fan, PAR-1224) now sends `utm_source` as `referrer` when the browser reports no referrer and the value is the host of an AI assistant `REFERRER_RULES` already puts in the `ai` channel, such as `chatgpt.com`. ChatGPT tags its links that way and often sends no referrer, so those visits counted as `direct`. The API code is unchanged: `classifyReferrer` sorts the host as before. The beacon also holds a page view until the page is on screen and drops tabs whose User-Agent names iOS or Android while `navigator.userAgentData` reports another system; in the first week, "Chrome on iOS" entered the glossary 468 times without a referrer against 12 for Safari. [Site analytics](frontend/site-analytics.md) says both, where it said before that no `utm_` parameter is read.
