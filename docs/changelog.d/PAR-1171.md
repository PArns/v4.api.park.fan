### Added — the site statistic marks hits from data centres and leaves them out unless asked

The collector counted a headless browser with an ordinary User-Agent as a reader. Every page-view and
event row now carries `network`, from the address's autonomous system: `datacenter` for the clouds
and hosters on `DATACENTER_ASNS` (37 networks, each checked against its RIPEstat holder), `other`
for any other, `unknown` without the ASN database and on older rows. The ASN comes from MaxMind
GeoLite2-ASN, downloaded and refreshed with GeoLite2-City by the same job; neither it nor the
address is kept. Nothing is dropped: every admin report, the live view and the MCP's `analytics_*`
tools leave the data centres' rows out by default and take `datacenter=include` or `only`, and the
window echoes the choice. A data centre's visitors count under scopes of their own (`dca`, `dde`),
so the default report reads the visitor rows it always read. The most-read rankings never count a
data centre's read. Networks whose traffic is people (iCloud Private Relay and WARP via Akamai,
Cloudflare and Fastly; the VPN networks M247 and Datacamp) are pinned off the list. On the first
deploy `synchronize` adds `network` with the default `unknown` to the four row tables, compressed
chunks included (tried on TimescaleDB 2.31). See [site statistic](frontend/site-analytics.md#data-centres).
