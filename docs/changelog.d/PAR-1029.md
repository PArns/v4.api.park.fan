### Fixed — a ride with no live wait reads `unknown`, and a ride that is down is never "best now"

A ride with no live wait (a `DOWN` ride, or one whose row carries no minutes)
took the model's crowd level for the current UTC hour as its live `crowdLevel`,
or `very_low` when there was none — "walk on" for a broken-down ride. It now
reads `unknown`, on the park payload and the attraction detail payload alike.
The forecast fallback on a failed baseline lookup in the detail payload is gone
for the same reason.

`bestVisitTimes` no longer offers the current 15-minute slot for a ride whose
`effectiveStatus` is not `OPERATING` (park payload, attraction detail and
favorites); later slots stay.

Frontend: render `unknown` as "no rating" and leave it out of any aggregate of
ride crowd levels. See `docs/frontend/ride-live-crowd-level.md`.

Items 2–4 of PAR-1029 (the first-hour blend) ship separately under PAR-1026.
