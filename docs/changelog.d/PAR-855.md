### Added — Admin model comparison: every model against what is served, per question, plus one real day

The forward archive could say how Chronos-2 did against the served curve, but
not whether H5, H5 with the TFT level, the old composer, persistence or a plain
weekday average beat what the app shows for a given question. The daily
scoring now pairs every archived model with **what is served for that
question** on identical slots of the same origin (`scorePairedModels`, into
`forecast_archive_paired`): persistence and the 06:00 shadows against the
served hourly curve on the live/today leads, the composer shadows and an
ex-ante **weekday average** against the served planner on d0–d60, best-time
regret per ride-day, and the planner's day peak for the calendar questions.
The weekday average uses only same-weekday dates strictly before the origin's
date, read from the hourly rollup (one bounded query per park, 15 ms for
Europa-Park). `GET /v1/admin/model-comparison` turns this into a matrix of ten
plain-German questions × eleven models with the park-cluster bootstrap CI, the
14-day / 10-park gate, the offline verdicts from the new
`src/ml/data/offline-model-verdicts.json` (ml-bench #445/#447/#450), a German
note per cell, the three switch checks and when the outstanding one reports.
`GET /v1/admin/model-comparison/day` replays one ride-day from one origin —
every archived curve on park-local quarter-hours against the measured waits,
with the MAE of each. See `docs/ml/forward-archive.md` §9.
