### Changed — the Postgres server log survives a deploy and reaches back a week

Postgres logged to stderr, which Docker kept in a size-capped ring buffer that
held about seven and a half hours and was deleted with the container. The
`log_lock_waits` lines added for the lock-queue outages were gone before anyone
looked. `logging_collector` now writes one file per weekday and hour into
`$PGDATA/log` on the bind mount; each file is emptied when its name comes round
a week later, which bounds the log to one week of output, about 0.7 GB at the
measured rate ([the Postgres server log](deployment/coolify.md#the-postgres-server-log)).
