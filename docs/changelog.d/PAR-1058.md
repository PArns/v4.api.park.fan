### Added — the driver-level model runs nightly as a calendar shadow

ml-bench's `driver_level` (PAR-830: the best day ranking of any level source in
both bench passes, but worse in spring, summer and at the best visit time) now
runs in production as a shadow, so the season measurement starts this autumn.
`ml-service/driver_level.py` ports the plug-in's features and model (parity
test on a fixture generated by the plug-in) and runs at 01:30 UTC on CPU in
its own process, started by the `forecast-archive` queue's `driver-level` job
via `POST /driver-level/run` (single-flight: a second call while a run lives
answers 409, which the job logs instead of failing); it replaces the new table
`driver_level_forecasts` (latest night only, no FK) with one level per ride for
the next 91 days. The 06:00 / 07:00 capture copies it into
`forecast_archive_curves.driver_day_peak` (nullable, never served), and the
scorer pairs it with the served day peak as `driver_level` — PEAK under the
TFT or CatBoost reference, D7 on TFT-levelled headliners. The model comparison
shows it as „Treiber-Niveau“ on `cal_rank`, `cal_busier`, `cal_far` and
`cal_far_90`, with offline verdicts from PAR-830, and the ML overview has the
decision `calendar_driver_level`, judged on 2027-09-01 (a summer window; spring
is read by hand in May 2027). See
[model comparison, paired scoring](ml/forward-archive/model-comparison.md#paired-scoring)
and [level drivers, the production shadow](ml/level-drivers.md#8-the-production-shadow-par-1058).
