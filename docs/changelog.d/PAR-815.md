### Fixed — CatBoost training registers its own metrics, fails honestly and stays inside its timeout

Four faults in the daily CatBoost training and serving path:

- **Old metrics under a new version.** The training processor read the new
  model's metrics from `/model/info`, which describes whatever model the
  answering worker has loaded. A worker only reloads on its next `/predict`, so
  after a 60 s wait the processor took the previous model's metrics and stored
  them under the new version. The champion/challenger gate then compared the
  champion with itself: `v20261006_0600` was stored with MAE 5.06, the value of
  `v20261003_0600`, while its own metadata file said 4.433 (also
  `v20260929`/`v20261001` and `v20260905`/`v20260906`). The ml-service now
  serves `GET /model/info/:version` from that version's own `.cbm` + `.pkl`, the
  processor registers from it, and a version with no saved metrics is not
  registered at all; the workers are pointed back at the DB-active model.
- **Phantom versions.** `train_standalone.py` reported `completed` and wrote
  the sentinel even when `train_model` returned early (no data, empty training
  set) and saved nothing. Workers then retried loading a missing file on every
  request. An early return is now a failure, and the sentinel is written only
  once the model file and metadata exist.
- **Training time ran into the timeout.** History starts 2025-12-24 and the
  window only closes at `TRAIN_LOOKBACK_YEARS` (2), so the pool grows every
  day: 1682 s on 2026-09-04, 2520 s on 2026-10-07 against a 2700 s limit. New
  `TRAIN_MAX_ROWS` (4.5M, about four weeks above today's ~3.9M) keeps the last
  `TRAIN_FULL_RESOLUTION_DAYS` (90) whole and thins older rows by a uniform
  seeded sample, so every month keeps its share and no season drops out. It
  runs after feature engineering, so lag and rolling features are unchanged.
  `ML_TRAINING_TIMEOUT_MINUTES` now defaults to 90.
- **HTTP 500 "dictionary changed size during iteration".** The recent-history
  caches in `predict.py` were iterated while another threadpool thread of the
  same worker inserted. Eviction now runs over a snapshot under a lock.
