### Fixed — park.fan may call the API from the browser, and setting CORS_ORIGINS no longer answers server-side callers with a 500

With `CORS_ORIGINS` set, the origin callback in `src/main.ts` raised an error
for every origin not on the list, and a request with no `Origin` header took
the same path. `cors` hands that error to Express, which answers 500, so every
server-side caller (park.fan's renders, the prewarm crons, scripts) would have
failed the moment the variable was set. `buildCorsOptions()`
(`src/common/cors/cors.config.ts`) now answers such a request normally without
CORS headers. Production allows `https://park.fan` and `https://www.park.fan`
when the variable is unset; `CORS_ORIGINS` replaces that list and takes `*`
inside one host label for the Vercel previews. Preflights carry
`Access-Control-Max-Age: 7200`. See `docs/deployment/cors.md`.
