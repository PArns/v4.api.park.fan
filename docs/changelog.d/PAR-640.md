### Fixed — a closed day with an evening event no longer reads as the event

Since PAR-276 the schedule cleanup keeps `TICKETED_EVENT`, `PRIVATE_EVENT`,
`EXTRA_HOURS`, `MAINTENANCE` and `INFO` rows beside the day's OPERATING,
CLOSED or UNKNOWN row. Seven readers took whichever row of the day came first
or last, and the enum order puts the event types before CLOSED and UNKNOWN.
They now read the row that states the day's status, OPERATING over CLOSED over
UNKNOWN (`pickDayStatusEntry` / `dayStatusRank` in
`src/common/utils/schedule.util.ts`):

- `isParkOperatingToday` filters on the three status types instead of a
  `findOne` with no type and no order.
- `storePredictions` no longer lets an event row read after CLOSED overwrite it,
  so a closed day's predictions are skipped again.
- The system accuracy stats test for a CLOSED day with an `EXISTS` instead of a
  join, so a prediction is counted once and not once per row of its day.
- The calendar day, the yearly closed-day set (`typeByDate`) and every
  `todaySchedule` in the park, discovery, location and favourites responses
  pick the status row.
- The calendar's refresh check no longer counts an event row as published hours.

Production on 2026-10-02 had 167 rows of the five event types and none of them
shared a day with a status row, so nothing changes until the next syncs keep one.
