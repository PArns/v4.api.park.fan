### Fixed — Weekly attraction-details sync no longer starves the live wait-times poll

`sync-attraction-details` (Sunday 05:30 UTC, one ThemeParks.wiki `/entity/{id}` request per attraction, ~7k) ran at 4 requests/s — the whole 240/min client cap — so for ~4.5 h every Sunday the 5-minute live poll waited behind it (230–430 s per sync instead of ~50 s, live cache warmup skipped). It now paces at one request every 2 s, leaving the live poll its budget; the run takes ~3.9 h, about what the cooldowns already made it take.
