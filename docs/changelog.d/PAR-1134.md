### Fixed — `nearby` drops retired rides; show and restaurant URLs point at a real route

`GET /v1/discovery/nearby` in the `in_park` case loaded every ride of the park,
retired ones included, and listed them as `CLOSED`; it now loads only rides with
`retiredAt IS NULL`. The favorites list built show and restaurant `url`s as
`/v1/parks/…/shows/<slug>` and `…/restaurants/<slug>`, routes this API does not
serve; both now carry their park's API path, and the two builders are gone. The
Swagger example of `/v1/discovery/geo` no longer shows `attractions[]` per park
or a site path as `url`, and `ParkReferenceDto.status` no longer lists
`REFURBISHMENT`, which it never sends ([discovery](frontend/discovery.md),
[favorites](frontend/favorites.md)).
