### Changed — `QueueData.attractionId` is declared as `uuid`

The entity declared `@Column({ type: "text" })` for `queue_data.attractionId`, while the production column is `uuid`. The relation's `@JoinColumn` creates the column, and TypeORM takes its type from `attractions.id`, so the `text` beside it never reached the schema. It only misled whoever joined against it: `a.id::text = qd."attractionId"` looked right and failed with `operator does not exist: text = uuid` (PAR-697 lost a query to it).

The decorator now says `uuid`. TypeORM's metadata for the column reads `uuid` before and after, so `synchronize` has nothing to change and no migration is needed. `queue_data_aggregates.attractionId` stays `text`, which is why `closed-park-days.sql.ts` keeps its `::text::uuid` detour. The comments in `outage-rows.sql.ts` and `plan-day.service.ts`, and the notes in `docs/admin/curation.md` and `docs/analytics/ride-downtime.md`, no longer describe a mismatch.
