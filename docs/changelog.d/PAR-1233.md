### Added — redirects from a dead park or ride path, made in the admin

`POST /v1/admin/redirects` takes a dead frontend path from the SEO not-found list and a park or ride
id, checks that the path has the right shape, is no live page and redirects nowhere else, and writes a
slug alias, so the park or ride lookup answers it with a 301. `DELETE /v1/admin/redirects?fromPath=`
undoes one. Until now an alias was only written as a side effect of a rename, a merge or the sync, and a
dead URL somebody spotted in the list had no way to be fixed from the admin. Both alias tables gained a
nullable `createdBy` column; only a row with one can be deleted, the history the sync and the merges
recorded cannot. The not-found report leaves out paths an alias now answers, so a fixed row disappears
instead of staying until its views age out of the window
([curation](admin/curation.md#redirects-from-a-dead-path)).
