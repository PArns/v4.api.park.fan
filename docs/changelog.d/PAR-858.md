### Security — close 21 Dependabot alerts, including a critical one in the request path

Dependabot held 21 open alerts on 2026-10-11 and `pnpm audit` counted the same
tree as 25 advisories (3 critical, 6 high, 12 moderate, 4 low). Twenty were npm
and one was pip, in `ml-bench/requirements.txt`, which only became visible once
PAR-827 landed. All but one are closed; the audit now reports a single advisory,
and it is one with no published fix.

Nothing in `src/` changed. Three packages needed only a lockfile move, because
the parent already declared a range the patched version satisfies: `proxy-addr`
2.0.7 → 2.0.8, `handlebars` 4.7.9 → 4.7.10 and `@grpc/grpc-js` 1.14.4 → 1.14.6.
`@testcontainers/postgresql` and `@testcontainers/redis` went 12.1.0 → 12.2.0,
which is the direct dependency that pulls `undici` — testcontainers 12.2.0
declares `^8.10.2` for itself, so the seven undici alerts and the two
`@grpc/grpc-js` ones close at their source rather than against a floor. The
remaining five are pinned exactly by their parent and so moved as `overrides` in
`pnpm-workspace.yaml`, each inside its current major: `multer` to `>=2.4.0`,
`brace-expansion` to `>=5.0.12`, the production 5.x `js-yaml` selector to
`>=5.4.1`, `fast-uri` to `>=4.1.5` and `undici`'s floor to `>=8.10.2`. A new
`proxy-addr: '>=2.0.8'` line holds that floor against a future re-resolve.

The four alerts on packages that reach production were each measured rather than
assumed, and none is exploitable as this app is wired. **proxy-addr**
(GHSA-jqcg-44mw-7w3h, critical) needs a trust subnet written as an IPv4-mapped
IPv6 address with a short prefix, which compiles to match every IPv4 address;
`src/main.ts` passes `trust proxy` the value `true`, not a subnet list, so that
path is never taken — and the rate limiters key on `CF-Connecting-IP` before
`req.ip` anyway. **brace-expansion** does run at boot, because TypeORM resolves
`entities: [__dirname + "/../**/*.entity{.ts,.js}"]` through glob and minimatch,
but all three advisories need an adversarial pattern and that literal is the only
pattern that reaches it. **js-yaml** is reached through `@nestjs/swagger`, which
calls only `dump()` to serialise our own OpenAPI document for `/api-yaml`, while
the advisory is in `load()`. **multer** ships with
`@nestjs/platform-express` and the advisory is about `diskStorage` on aborted
uploads, but the API has no upload route at all — no `FileInterceptor`, no
`UploadedFile`, nowhere in `src/`.

`sprintf-js` (GHSA-hp3w-g68c-fv3c, moderate) stays open and is the one remaining
advisory. The advisory covers `<=1.1.3` and 1.1.3 is the highest version ever
published, so there is no release to move to; `pnpm audit` naming `>=1.1.4` as
the patched range points at a version that does not exist. It is dev-only and
four levels deep under jest — `jest > @jest/transform > babel-plugin-istanbul >
@istanbuljs/load-nyc-config > js-yaml > argparse > sprintf-js` — where argparse
formats jest's own help strings. Left in place deliberately rather than pinned
away.

`pytest` in `ml-bench` went 8.3.4 → 9.0.3 (CVE-2025-71176, predictable
`/tmp/pytest-of-{user}` directories). That crosses a major, which is safe here on
two counts: `ml-bench` is an offline benchmark that is not deployed and carries
no `docker-compose` entry, and its 27 tests pass identically under both versions,
measured in a throwaway container. Its `pytest.ini` sets only `testpaths`, so
there is no deprecated configuration for 9 to reject.
