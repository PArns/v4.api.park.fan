### Fixed — CatBoost training stops paying for 2000 trees it never converged in

Early stopping never fired: every nightly model since at least 2026-09-28 has `best_iteration` 1999 of 2000, so the fit (~28 min) and the refit on all rows (~36 min) both ran the full cap, ~73 of the 90-minute timeout. The wiring was correct — eval set, `od_wait` 100, `use_best_model`, eval metric = the MultiQuantile loss — but at learning rate 0.03 the validation loss, and the 30-day out-of-time hold-out with it, were still falling past 3000 trees. Measured on the production frame of 2026-10-15 (4.44 M rows), `0.1 × 1500` beats the old `0.03 × 2000` on hold-out MAE (4.33 vs 4.36), busy hold-out MAE (15.17 vs 15.61) and validation MAE (4.39 vs 4.55) with 25 % fewer trees, so a nightly run should take ~57 min instead of ~73. The eval set stays the random validation weeks: they track the hold-out tree for tree, so the gate keeps comparing the same measurement. `od_wait` is now `CATBOOST_EARLY_STOPPING_ROUNDS`, and what the detector did is saved in the model metadata (`early_stopping`) and in `training_timings.fit` instead of only in a log a redeploy deletes. New `tests/test_early_stopping.py`.
