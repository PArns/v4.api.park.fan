### Changed — The admin's queue screen tells an old failure from a current one

Bull keeps a failed job until newer failures push it out, which on a quiet
queue is never, and the queue screen showed each one red with no date. On 30
October three queues were red: `search-console` for a click from 28 October,
fixed the next morning; `ml-training` for a training on 24 October, fixed the
same afternoon and trained every day since; and `children-metadata` for the
weekly sync of 25 October that has not run again. `queue-status` now adds
`failedOpen`, the failures no later run of the same job has succeeded since,
and `queue-failures` gives each failure `failedAt` and `succeededSince`. The
rule is the data-quality report's, now in one helper both read
(`src/queues/queue-job-history.ts`). See the
[admin endpoints](admin/endpoints.md).
