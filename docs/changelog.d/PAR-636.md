### Fixed — `POST /v1/admin/cache/reset` no longer deletes the Bull queues

The handler ran `FLUSHALL`, while its docblock said queue jobs were not
affected. Bull keeps every queue under `<BULL_PREFIX>:<queue>:*` in the same
Redis, so a reset deleted all jobs and `repeat` entries, and no cron ran again
until the API restarted. It also logged out every admin session. The reset now
deletes the same `PARK_CACHE_FLUSH_PATTERNS` as `POST /v1/admin/flush-cache`
and then queues the four rebuild jobs as before. Both endpoints walk the
keyspace with SCAN instead of KEYS (`src/admin/delete-keys-by-patterns.ts`).
The response gains `keysDeleted`. `cache-reset.spec.ts` checks that Bull keys
and admin sessions survive a reset and that `FLUSHALL` is never called.
