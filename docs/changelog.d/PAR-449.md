### Documented — the hourly confidence's time term is a distance, not an error estimate

`predict.py` computes the time term of the hourly `confidence` as `max(50, 95 - hours_ahead * 2)`. It reaches its floor at 22.5 h, so 103 of the 192 slots in the 48 h horizon (53.6%) carry the same value. Measured against `prediction_accuracy` (hourly, COMPLETED, 30 days), the error over the first 24 h rises 4.9% (10.913 to 11.453, 421 attractions with at least 30 cases in each of eight 3 h bands) while the term falls 47% (94.5 to 50). Beyond 24 h the error cannot be measured, because `recordPredictions` keeps only the latest prediction per target time (PAR-658).

The curve is unchanged and no served value moves. The code comment in `predict.py` and the Swagger description of `PredictionDto.confidence` now say that the term expresses how far ahead a prediction is, not how accurate it is. Making `confidence` null beyond 24 h would change a public API contract and is decided separately.
