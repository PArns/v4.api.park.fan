### Fixed — a restaurant's reservation requirement is unknown, not "no"

`ThemeParksMapper.mapRestaurant` wrote `requiresReservation: false` for every
restaurant, though ThemeParks.wiki never sends the fact: an invented "walk-ins
welcome" ([absent facts](rules/absent-facts.md)). It now writes `null`, the
column is nullable without a default (`DB_SYNCHRONIZE` drops `NOT NULL` and the
default on deploy), and the park payload's `restaurants[].requiresReservation`
is `boolean | null`, so unknown arrives absent. Existing rows are not rewritten
by SQL; the next children sync sets them to `null`. The
[restaurant contract](frontend/restaurants.md) says how a client reads absent.
A source for cuisines and reservations is still open.
