### Fixed — the nightly closure reconstruction stores a closure that began before the opening

The live closure line has, since PAR-913, started a closure that began before the park opened at the
opening (Phantasialand's Pferdekarussell: `CLOSED` from 08:55, park open from 09:00). The nightly
`CLOSURE_GAP_INTERVALS_SQL` still required the start inside a window, so those closures were shown and
never stored, and the `closed_gap` recovery curve never learned from them. `gap_edges` now uses the
live `run_window` rule: the first window that opens later the same park-local day, the same `night_mid`
test on the ride's last `OPERATING` reading, `startedAt` clipped to the opening, and only for a ride
still `CLOSED` when the park opened. A start after the day's last close stays out, as it does live.
Simultaneity is counted on the raw minute. See
[the closure-gap signal](analytics/ride-downtime/closure-gap-signal.md). How many intervals the
fallback adds over 60 days, and the statement's runtime before and after, are still to be measured
against production.
