### Fixed — the park attractions list schema no longer promises live fields

Since PAR-184, `GET /v1/parks/{continent}/{country}/{city}/{parkSlug}/attractions` leaves out `status`, `hourlyForecast`, `forecasts` and `statistics`, but its OpenAPI schema still pointed at the full `AttractionResponseDto`, so a client generated from `api-json` typed all four on this route. The route's `items` now reference `ParkAttractionListItemDto`, an `OmitType` of the full DTO whose key list comes from `AttractionResponseDto.livePlaceholders()`: 40 properties instead of 44. The detail route and every other schema the parks controller emits are unchanged against the live `api-json`.
